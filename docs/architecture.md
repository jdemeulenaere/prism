# Prism Planned Architecture

This document holds the **planned** design of Prism subsystems that are **not implemented yet**. It is the counterpart of [`openspec/specs/`](../openspec/specs), which describes only behavior the compiler implements today.

- **Nothing in this document is implemented**, except sections 4 and 5, which say so at their top and keep only the rationale of what was built. Treat the rest as design intent, not as a description of the code.
- Requirements keep the OpenSpec `Requirement` / `WHEN` / `THEN` form so they can be copied into a change's delta specs.
- When an OpenSpec change implements a requirement, its delta spec adds it to `openspec/specs/` and the change removes it from this document.
- Progress is tracked in [`ROADMAP.md`](../ROADMAP.md). The non-negotiable invariants these designs must respect live in [`openspec/specs/system-invariants`](../openspec/specs/system-invariants/spec.md).

## 1. Compilation Pipeline & Compilation Avoidance

Implemented today (see [`compilation-and-abi`](../openspec/specs/compilation-and-abi/spec.md)): Phase 1 ABI extraction, a deterministic 256-bit BLAKE3 ABI hash covering no body, and the first three stages of the Phase 2 semantic pipeline: the typed tree ([`typed-tree`](../openspec/specs/typed-tree/spec.md)), MIR ([`mir`](../openspec/specs/mir/spec.md)), and borrow checking each file's MIR alone for uses of moved and uninitialized values, followed by drop elaboration (`borrowck-moves`, [`compilation-and-abi`](../openspec/specs/compilation-and-abi/spec.md) and [`ownership`](../openspec/specs/ownership/spec.md)), and then for borrow conflicts and escaping closures on the elaborated MIR (`borrowck-exclusivity`, [`references`](../openspec/specs/references/spec.md)). Generic declarations are checked once, against their bounds, into polymorphic typed trees and MIR, with their signatures and marker parameters in the ABI ([`generics`](../openspec/specs/generics/spec.md)), and `prism run` compiles one instance per generic and list of concrete type arguments the program uses, each a code unit of its own with its own function-table slot, built from the generic's record (its elaborated polymorphic MIR and the type definitions it mentions) and its arguments' definitions alone (`monomorphization`, [`compilation-and-abi`](../openspec/specs/compilation-and-abi/spec.md) and [`code-generation`](../openspec/specs/code-generation/spec.md)). `prism check` and `prism run` avoid work through a per-user build cache ([`build-cache`](../openspec/specs/build-cache/spec.md), `abi-cache` and `instance-cache`): a file's Phase 2 is skipped when the cache holds a passing verdict for its content, module path and direct imports' ABI hashes, with the file's summary, from which both commands plan the program's instances and find `E6004`. Phase 3 generates each file's code from its own elaborated MIR, as one code unit per file (`codegen-core`, [`code-generation`](../openspec/specs/code-generation/spec.md)), holding no instance, and both file units and instance units are cached as relocatable artifacts keyed by their check key or by their generic's Monomorphization Hash (a hash of its record) and their type arguments' definitions, plus the target identity, so a generic body edit regenerates that generic's instances alone and rebuilds no importer ([`compilation-and-abi`](../openspec/specs/compilation-and-abi/spec.md), `instance-cache`). The callee's side of returned borrows is planned in section 3. Everything below is planned.

### Requirement: Parallel Phase 2 Body Compilation
After Phase 1 completes, function bodies MUST be lowered and compiled in parallel against the imported ABI hashes.

#### Scenario: Phase 2 body lowering
- **WHEN** Phase 1 completes
- **THEN** function bodies are typechecked and compiled in parallel against the imported ABI hashes

## 2. Two-Tier Native Execution

Implemented today (`codegen-core`, `codegen-aggregates`, `runtime-strings-and-drops`, `heap-boxes`, `string-templates`, `monomorphization`, `closures` and `hot-reload`, [`code-generation`](../openspec/specs/code-generation/spec.md), [`execution`](../openspec/specs/execution/spec.md) and [`hot-reload`](../openspec/specs/hot-reload/spec.md)): the Tier 1 Cranelift JIT behind `prism run`, for programs over `Int`, `Double`, `Bool`, `Char`, `String` (with string templates built by one runtime call and one allocation), structs, enums, nullables, `Heap<T>` boxes and references to them, reaching `main` well under 15 ms, with drop and clone glue freeing owned memory deterministically and `prism run --check-allocations` verifying it; every call goes through a patchable function table and nothing is inlined, which hot reload needs. Generic code runs as instances, one per list of type arguments (`monomorphization`), and closures and function values run as a descriptor address and an environment address, each closure's code with its own slot, so stored function values follow a reload (`closures`); composables compile and run with a composer and change words (`compose-transform`). `prism run` loads the code of every unit and instance whose inputs are unchanged from the build cache, so a warm run of an unchanged program compiles nothing (`instance-cache`). `prism run --watch` keeps a program running while its files change: it compiles only the units whose code key changed into a new JIT module and the program thread applies the reload at its next call; slots keep the contract of their code, so a changed signature or changed captures give the symbol a new slot while running frames and old function values keep the old code, top-level values live in a program-owned value table and are kept unless their type or initializer changed, and old modules stay mapped while the program runs (`hot-reload`). Tier 2 is planned below.

### Requirement: Two-Tier Native Execution Engine
The compiler MUST support two distinct native execution backends: Tier 1 (Cranelift JIT) for development and Tier 2 (LLVM AOT) for release.

Tier 1's side, calls through a patchable function table with nothing inlined and their patching under `prism run --watch`, is specified in `code-generation` and `hot-reload`; what remains planned is Tier 2.

#### Scenario: Tier 2 release optimization
- **WHEN** the user builds with `prism build --release`
- **THEN** the compiler invokes the LLVM backend with whole-program optimization and Link-Time Optimization (LTO)

## 3. Memory Model & Resource Management

Compile-time memory safety: zero runtime garbage collection, zero hidden automatic reference counting (ARC), single-owner value semantics, stack-confined borrows with automatic lifetime elision, and data-oriented handles.

Implemented today: rejecting borrowed fields in structs ([`syntax`](../openspec/specs/syntax/spec.md)); basic borrow type compatibility, including rejecting `&mut` of a `val` and requiring `&mut` on an argument passed to a `&mut T` parameter (`E4004`, [`type-system`](../openspec/specs/type-system/spec.md)); and, from `value-semantics`, the `: Copy` and `: Clone` markers, the built-in `Copy` and `Clone` tables, explicit `.clone()`, whole-value moves (`E4017`) and immutable top-level declarations ([`ownership`](../openspec/specs/ownership/spec.md)); and, from `reference-access`, implicit shared borrows at argument sites, copy-out of `Copy` values from borrows, moving out of a borrow (`E4017`), prefix `*` for writes, re-pointing `var` references, reborrowing `&mut` arguments, the `&(T?)` to `(&T)?` view and invariant references ([`references`](../openspec/specs/references/spec.md)); and, from `extension-methods`, methods as extension functions whose receivers are borrowed shared, borrowed mutably or moved by their `fun` / `mut fun` / `consuming fun` mode with nothing written at the call site ([`extension-functions`](../openspec/specs/extension-functions/spec.md), [`references`](../openspec/specs/references/spec.md), [`ownership`](../openspec/specs/ownership/spec.md)); and, from `borrowck-moves`, single-owner values checked by the borrow checker: use after move (`E5001`) through branches, loops, consuming receivers and closure captures, reinitialization by assignment, uninitialized reads (`E5002`), and drops elaborated so that each value is dropped exactly once where its owner's scope ends ([`ownership`](../openspec/specs/ownership/spec.md), [`mir`](../openspec/specs/mir/spec.md)); and, from `borrowck-exclusivity`, stack-scoped borrows checked by the borrow checker: any number of shared borrows or one mutable borrow, each lasting until the last use of the references holding it, with conflicting borrows and reads (`E5003`), assignments and moves of borrowed values (`E5004`, `E5005`) and values that end while borrowed (`E5006`) rejected, disjoint field borrows, two-phase receiver borrows, call results that keep their input borrows (the caller's half of the elision rules), closures that capture by inferred borrow and never move a capture (`E4017`), and capturing closures and function-typed parameters that cannot escape (`E5007`) ([`references`](../openspec/specs/references/spec.md), [`ownership`](../openspec/specs/ownership/spec.md), [`mir`](../openspec/specs/mir/spec.md)); and, from `borrowck-elision`, the four lifetime elision rules from signatures alone, for callers and callees, with returned borrows of locals, temporaries and by-value parameters (`E5008` `DanglingBorrowReturn`) and returned borrows derived from untied inputs (`E5009`) rejected, function types eliding by the same rules, defaults borrowing only through shared references, and borrows of top-level `val`s valid everywhere ([`references`](../openspec/specs/references/spec.md)); and, from `runtime-strings-and-drops`, deterministic cleanup at run time: each drop the elaborated MIR keeps runs the value's drop glue, freeing its owned memory where its owner's scope ends, where it is overwritten (`*r = v` drops the old referent) or in the code it was moved to, `clone()` builds values sharing no owned memory, top-level values are never dropped, and `prism run --check-allocations` checks that every allocation is freed exactly once ([`execution`](../openspec/specs/execution/spec.md), [`code-generation`](../openspec/specs/code-generation/spec.md)); and, from `heap-boxes`, `Heap<T>` as the single-owner heap allocation of recursive data: `Heap(value)`, boxes read like references to their contents, `*h = v` writes them, `h.unbox()` and consuming receivers move them out, patterns look through boxes, boxes are invariant, and dropping a box drops its contents then frees it, cloning allocates a new box holding a clone, with no reference counting ([`type-system`](../openspec/specs/type-system/spec.md), [`references`](../openspec/specs/references/spec.md), [`ownership`](../openspec/specs/ownership/spec.md), [`patterns`](../openspec/specs/patterns/spec.md), [`execution`](../openspec/specs/execution/spec.md), [`code-generation`](../openspec/specs/code-generation/spec.md)); and, from `escaping-closures`, closures that own their captures where they escape or outlive a captured binding, decided from the source by the type checker in linear time, `escaping` function-typed parameters, `E5007` only for escaping values that may hold a borrow, `E4028` for captures a closure cannot take by value, and owned environments in one exact-sized allocation freed by the closure's drop function, or held in the function value's environment word when they fit one word and need no drop ([`references`](../openspec/specs/references/spec.md), [`ownership`](../openspec/specs/ownership/spec.md), [`type-system`](../openspec/specs/type-system/spec.md), [`code-generation`](../openspec/specs/code-generation/spec.md), [`execution`](../openspec/specs/execution/spec.md)); and, from `receiver-lambdas`, the receivers of function values with a receiver and context arguments borrowed as extension receivers are, and receiver function types eliding exactly as their plain forms ([`references`](../openspec/specs/references/spec.md)); and, from `state-handles`, the state handles `State<T>` and `MutableState<T>`, `Copy` 64-bit generational handles of cells in an arena the compose runtime owns, each cell with one owner (the `remember` slot, composition or program that created it) and freed exactly once, a borrow of a cell's value valid for the body that took it during composition and guarded by run-time flags elsewhere ([`compose`](../openspec/specs/compose/spec.md), [`references`](../openspec/specs/references/spec.md)); and, from `ui-toolkit`, the node handle `NodeId`, a `Copy` one-word generational handle (a 32-bit index and a 32-bit generation) into the node arena `prism-ui` owns, `package` to the toolkit modules until a public layout API hands one out, with nodes owning their strings and the handlers they claim ([`ui`](../openspec/specs/ui/spec.md), [`standard-library`](../openspec/specs/standard-library/spec.md)); and, from `path-captures`, closures that capture paths (fields, box dereferences and a `val` reference's first dereference) rather than whole bindings, borrowing them disjointly, and owning closures that copy the `Copy` paths no later write could change and otherwise own the whole binding, with no partial moves ([`references`](../openspec/specs/references/spec.md), [`ownership`](../openspec/specs/ownership/spec.md)). Everything below is planned.

The "road to the borrow checker" in [`ROADMAP.md`](../ROADMAP.md), agreed with the user on 2026-10-17, is complete, and closures that escape own their captures since `escaping-closures`. Flow-insensitive rules are type errors (`E4xxx`, in the type checker); flow-sensitive ones are borrow-checker errors (`E5xxx`, see section 1 for the pipeline).

### Requirement: Data-Oriented Typed Handles for Graphs
Graph topologies and cyclic data structures MUST use typed integer/handle IDs instead of raw pointers or reference-counting pointer cycles.

#### Scenario: Peer node reference via typed ID
- **WHEN** a struct references another struct via a typed identifier (`val parentId: NodeId?`)
- **THEN** no cyclic pointer graphs are formed and memory is managed by the owning collection

### Design notes (2026-10-17 exploration)
Why the requirements above were chosen; each change's `design.md` repeats the decisions it implements.

- **`&String?` parses as `&(String?)`.** Postfix binds tighter than prefix, as in expressions (`&x.y` borrows `x.y`), and `&mut String?` is the natural type for a mutable nullable slot. An optional borrow is written `(&String)?`.

## 4. Runtime Semantics

Implemented: the runtime semantics of every construct the type checker accepts and the Tier 1 backend runs, over scalars, strings, structs, enums, nullables, boxes and references to them, are in [`execution`](../openspec/specs/execution/spec.md) and [`loops`](../openspec/specs/loops/spec.md) (`codegen-core`, `codegen-aggregates`, `runtime-strings-and-drops`, `payload-patterns`, `heap-boxes`, `string-templates`, `monomorphization`, `closures`, `escaping-closures`, `receiver-lambdas`), and their layouts, drop glue and clone glue in [`code-generation`](../openspec/specs/code-generation/spec.md). The order of evaluation, including when receivers are evaluated and borrowed, and where each temporary is dropped are fixed by the MIR ([`mir`](../openspec/specs/mir/spec.md)), which the backend follows. Nothing remains planned here: the runtime semantics of composable functions come with the compose changes (section 5).

### Design notes (2026-10-18 compose architecture)
Why the plan was chosen, with the alternatives rejected; each is a `compose-architecture` row in [`docs/decisions-for-review.md`](decisions-for-review.md), and each change's `design.md` repeats the decisions it implements.

- **D1. Rust runtime crates, split by concern.** The composer, slot table and cell arena are data-structure code that needs raw memory and type-erased values, which Prism cannot express before traits, collections and an unsafe layer exist; a Prism runtime would also wait for self-hosting. `prism-compose` is UI-agnostic (its `Node` groups hold opaque node handles from an applier that `prism-ui` provides, and a test applier in unit tests), so it can later drive other trees. The window is its own crate so that headless tests and Tier 2 apps without windows build without `winit` (implemented by `desktop-window`). Rejected: a compose runtime written in Prism, one crate for everything.
- **D2. A bundled standard library with a compose prelude.** (The library, its prelude and the `external` and `intrinsic` forms are implemented by `standard-library`, whose spec's Design Rationale records how; the compose prelude module came with `compose-transform`; `explicit-library` removed the prelude, so every library module is imported, and moved the sources to the top-level `library/`.) Declaring the toolkit in Prism source gives named parameters, defaults, the ABI, `prism fmt` and later the LSP for free, and composables written in Prism exercise the transform and hot reload; hand-written type-checker tables (as for `print` and `Range`) do not scale to dozens of declarations with defaults. `external` is the runtime entry point form an FFI and a self-hosted standard library will need anyway, and `intrinsic` keeps a declared signature for what the compiler lowers itself (state members need special typing, `remember` and `key` need the composer). The compose primitives are a prelude because compose is part of the language (the first-class compose invariant), while the toolkit is a library imported like any package. The bundled files are covered by the compiler version, which every artifact key holds, so the deterministic hermetic builds invariant is kept. Rejected: global built-ins in the type checker, auto-importing the toolkit, an `import /prism/compose` in every composable file.
- **D3. The transform is a MIR pass after borrow checking, before instantiation (revised for compile speed 2026-10-19).** (Implemented by `compose-transform`, whose decisions are in the Design Rationale of [`compose`](../openspec/specs/compose/spec.md) and [`mir`](../openspec/specs/mir/spec.md).) The borrow checker should not see composer plumbing (the composer is runtime memory reached by address), and skipping needs the parameter drops elaboration placed (a skipped body still drops its owned arguments), so the pass runs on each body's elaborated MIR. It runs once per body, before `monomorphization`: a generic composable is transformed once and its record holds the composed MIR, which each instance only substitutes, and `instance-cache` keys and stores that. Stability is read from declared markers (D9), so it needs no concrete type: a type-parameter parameter is stable exactly when it is bounded `Copy`, and the `==` that compares it is lowered per instance by the backend like any `==` on a substituted type. `prism dump-mir --composed` makes it snapshot-testable. The first version ran the pass on each unit's concrete MIR after instantiation, so that stability was decided per instance: that repeats the transform for every instance of a generic composable and makes an instance's code depend on a stability decision taken per type argument; the revision costs a `T : Copy` bound on a generic composable that should skip (Jetpack instead infers stability per type argument at run time). Rejected: rewriting the typed tree as Kotlin's IR plugin rewrites IR (the borrow checker would check the plumbing), generating it only in Cranelift (untestable), transforming after instantiation (above).
- **D4. An explicit composer parameter.** (Implemented by `compose-transform`, whose decisions are in the Design Rationale of [`compose`](../openspec/specs/compose/spec.md) and [`mir`](../openspec/specs/mir/spec.md).) Passing the composer and change words keeps several compositions (windows, tests) independent and costs no thread-local lookup per call. Default values are generated by the caller (`mir-lowering`), so Jetpack's default mask is not needed. Rejected: a thread-local current composer, which would keep composable signatures unchanged but hide which composition a call belongs to. The composer is a word, the validated identifier of the pass in progress, rather than an address (`compose-runtime` D3), so the protocol is memory-safe for any caller.
- **D5. Keys from declaration paths and lexical paths.** (Implemented by `compose-transform`, whose decisions are in the Design Rationale of [`compose`](../openspec/specs/compose/spec.md) and [`mir`](../openspec/specs/mir/spec.md).) Jetpack hashes source offsets, which every edit above a call changes, losing state on hot reload. A key made of the body symbol (the identity MIR gives bodies, `mir-lowering`), the construct path and the ordinal among same-callee siblings survives formatting, comments, argument edits and inserted calls of other callees. Keys only decide which state is reused; type fingerprints make a wrong match safe. Rejected: source offsets, a per-body call index (an inserted call shifts every later key).
- **D6. A generational arena tree as the slot table.** (Implemented by `compose-runtime`, whose decisions are in the Design Rationale of [`compose`](../openspec/specs/compose/spec.md).) Groups with parent and child links make moves, keyed lookup and restart anchors simple, and generational group ids serve as restart scope handles; Jetpack itself is moving from its gap buffer to a linked table. The representation is behind the `prism_compose_*` entry points, so it can change without touching the transform. Removals are deferred to the end of the pass so that borrows taken during the pass stay valid (D13). Rejected: Jetpack's gap buffer of groups and slots (anchors and gap moves for little benefit at this scale).
- **D7. Node changes applied during composition.** (Implemented by `compose-runtime`, whose decisions are in the Design Rationale of [`compose`](../openspec/specs/compose/spec.md).) Jetpack records a change list and applies it through an `Applier` afterwards so that a composition can be abandoned or run concurrently; Prism composes on one thread and never abandons a pass, so applying directly is simpler. Rejected: a recorded change list.
- **D8. `remember` keeps `Copy` values only.** (Implemented by `compose-transform`, whose decisions are in the Design Rationale of [`compose`](../openspec/specs/compose/spec.md) and [`mir`](../openspec/specs/mir/spec.md); revised by `owned-state`, under which `remember` keeps any value and gives a `&T` of a non-`Copy` one, borrowed from its slot for the rest of the body.) Returning a remembered non-`Copy` value would need a borrow tied to the composer, which conflicts with every later composable call, or a hidden clone. Handles are `Copy`, so `remember { mutableStateOf(list) }` covers non-`Copy` data, and type arguments are already borrow-free (`E4022`). Rejected: `remember` returning `&T`, remembering non-`Copy` values returned by move once.
- **D9. Stability without clones.** (Implemented by `compose-transform`, whose decisions are in the Design Rationale of [`compose`](../openspec/specs/compose/spec.md) and [`mir`](../openspec/specs/mir/spec.md); revised by `strong-skipping`, review item A1: there is no stability notion any more, and every composable whose parameters can be kept skips, a borrowed parameter kept as its address and its source's version, still without clones or deep comparison; its decisions are in the same Design Rationale sections.) Jetpack compares parameters by reference or `equals`, which a GC makes free; in Prism keeping a non-`Copy` argument to compare it later would mean a hidden clone, against the explicit `.clone()` rule of `ownership`. `Copy` values are kept by copy, and closures whose environments hold only `Copy` captures (the common `{ count.value += 1 }`) by descriptor and environment copy, compared by a per-closure equality entry that `compose-transform` adds to closure descriptors (D3 of `closures`); such an environment of one word is held in the function value itself (`code-generation`, "Small Owned Environments Are Held in the Function Value"), so the comparison is a word compare. Two change bits per parameter let callers pass "static" for literals and top-level values and "same" for forwarded unchanged parameters. Stability is read from the declared `Copy` marker, which Prism already requires for copying, so it costs one lookup per parameter type and no analysis: Jetpack's compiler instead infers the stability of every class from its fields, across modules, and needs `@Stable` and `@Immutable` annotations and stability configuration files where inference fails; the declared marker plays their role here. Rejected: keeping clones of `Clone` parameters (a later opt-in), comparing hashes (unsound), never skipping, inferring stability from fields (a whole-program analysis that makes a composable's skipping depend on other files' private fields).
- **D10. Restart scopes only where parameters are kept.** (Implemented by `compose-transform`, whose decisions are in the Design Rationale of [`compose`](../openspec/specs/compose/spec.md) and [`mir`](../openspec/specs/mir/spec.md).) Restarting a body needs its arguments; only stable ones are kept, so a composable with other parameters is not a restart scope and its reads invalidate the nearest one above it, which reruns it with fresh arguments. Content lambdas borrow their author's frame, so they are not restart scopes either (Jetpack's restartable lambdas rely on the GC), and the author recomposes instead. Rejected: restarting only at the root (correct but every change recomposes the whole tree), restartable lambdas.
- **D11. Compositions are owned values.** (Implemented by `compose-transform`, whose decisions are in the Design Rationale of [`compose`](../openspec/specs/compose/spec.md) and [`mir`](../openspec/specs/mir/spec.md).) An owned `Composition` gives disposal a place (its drop), lets tests drive passes from `main` before the toolkit exists (`compose-transform` and `state-handles` test through `composition`, `setContent` and `recompose`), and allows several compositions. Rejected: one global composition started by `runApp` only.
- **D12. Two handle types, one word each.** (Implemented by `state-handles`, whose decisions are in the Design Rationale of [`compose`](../openspec/specs/compose/spec.md); revised by `owned-state`, under which `State<T>` and `MutableState<T>` are owned, move-only objects of one word, passed by borrow, compared by identity, with `WeakReference<T>` the `Copy` handle.) `MutableState<T>` and `State<T>` follow Kotlin, and a read-only parameter says a composable does not write; both are the same 64-bit word, so the conversion is a subtype step like `&mut T` to `&T`. Generations catch handles that outlive their cell at the cost of a compare per access, where Rust's `slotmap` has the same check. Rejected: one mutable type, owning (non-`Copy`) state values, which the state-handle invariant excludes.
- **D13. Borrowing state contents during composition.** (Implemented by `state-handles`, which refines it: a `Copy` value is read as a copy anywhere, and only a non-`Copy` one is a place, borrowable in composable contexts and reached through `read`, `update` and `edit` elsewhere, with `E4033` naming them; see the Design Rationale of [`compose`](../openspec/specs/compose/spec.md). Revised by `owned-state`: a non-`Copy` value is a place in every context, borrowed through the state object, and outside composable contexts each borrow holds the state's run-time flag for as long as it lives; `read`, `edit` and `E4033` are gone.) During composition no state can be written (D14) and no cell is freed before the pass ends (D6), and a borrow cannot leave the body it was taken in (escaping closures hold no borrows, `E5007`; a returned borrow needs a borrowed input, `E5009`; struct fields cannot be borrows), so a shared borrow of `s.value` in a composable context is valid for the whole body, which allows `for (todo in todos.value)` as in Kotlin. Outside composition handlers can write any cell through any copy of a handle, which no static check can see, so access goes through `read`, `update` and `edit` closures, whose runtime borrow flag catches re-entrant access the way `RefCell` does. Rejected: run-time-checked place borrows released at their last use (needs the borrow checker to emit releases), a closure-only API (no `for` over a list state in composables).
- **D14. State is read-only during composition.** (Implemented by `state-handles`, with `E4031` and `E4032` and the run-time errors `state written during composition` and `state created during composition outside remember`.) Jetpack allows writes during composition through its snapshot system and warns about backward writes; without snapshots a write during the pass would invalidate borrows (D13) and produce order-dependent results. `mutableStateOf` in a composable context is always the unremembered-state bug that Jetpack's lint reports, so it is an error. Side effects belong in handlers (and later in effect APIs). Rejected: allowing writes, deferring writes to the end of the pass.
- **D15. Cells belong to their creator.** (Implemented by `state-handles`, with top-level initializers running as program code and program cells freed only under the allocation check; revised by `owned-state`, under which a state object is owned like any value, by a local, a field, a list element or a `remember` slot, and dropping it retires its cell, freed at the end of the next pass.) Ownership by the creating `remember` slot gives every cell a single owner with no counting, like Solid's ownership tree. Cells made in handlers belong to their composition, so an app that creates states in handlers keeps them until it ends; an explicit release or state values owned by data structures is a later option if apps need it. Rejected: reference counting (against the zero hidden ARC invariant), rejecting `mutableStateOf` outside `remember` (handlers legitimately create state).
- **D16. No snapshot system.** (The state half is implemented by `state-handles`, which refines the comparison: the runtime makes it, calling the equality entry of the cell's slot type record that every write passes anyway, so no write site holds comparison code.) One program thread runs compositions and handlers, so there is nothing to isolate; reads register the innermost restart scope, writes invalidate readers, and an equal `value =` write invalidates nothing (Jetpack's structural equality policy). The comparison is a call of the value type's equality glue at the write site, inline only for scalars (revised for compile speed 2026-10-19: the first version expanded it inline at every write site, which repeats code per site and, for large structs, is super-linear in the type's size, the cost the `codegen-aggregates` follow-up on per-type equality measured). Every equality the compose runtime needs, for skipping (D9), `remember` keys and handler captures, goes through the same glue. `update` and `edit` always invalidate. Rejected: Jetpack's MVCC snapshots, until threads exist.
- **D17. Toolkit composables in Prism over one node primitive.** (Implemented by `ui-toolkit` over two primitives, `Node` and `LeafNode`, with Material components written over foundation and layout; see the Design Rationale of [`ui`](../openspec/specs/ui/spec.md).) `Node(kind, update, content)` plus `external` property setters keep the Rust surface small and let `Column` and `Button` be ordinary, hot-reloadable composables. `Checkbox` and a single-line `TextField` (printable characters, backspace, enter; no selection or IME) are included because the todo app needs them. Rejected: composables implemented in Rust, an `Applier` interface in Prism.
- **D18. Modifiers as a `Copy` property struct.** Jetpack's ordered modifier chain (`padding` then `background` differs from the reverse) needs an allocated list per call and makes every composable taking one unstable here (D9); a `Copy` struct of order-insensitive properties allocates nothing, compares by `==` and covers padding, size, fill, background and border. The demo's `Column(padding = 16)` becomes `Column(modifier = Modifier().padding(16))` (the empty value's spelling is `ui-toolkit`'s). Rejected: an ordered chain (a later extension), named layout parameters on every composable. (Superseded; implemented as revised 2026-10-19 by user direction in `ui-toolkit` D6, D23 and D25: `Modifier` is Compose's ordered chain after all, a `Copy` value of up to 16 plain data elements compared element by element; handlers live in a table of `prism-ui` named by a `Copy` `HandlerId`, so the chain stays `Copy` and stable; and no modifier runs composition, unlike the deprecated `Modifier.composed`.)
- **D19. Single-pass constraint layout.** (Implemented by `ui-toolkit`, which measures text through an interface with fixed advances headless instead of the bundled font everywhere, and relayouts incrementally; see [`ui`](../openspec/specs/ui/spec.md).) Parent constraints and child sizes, as in Jetpack and Flutter, cover columns, rows, boxes, padding, fixed and filling sizes and wrapped text, with a measure cache; integer logical pixels keep dumps exact. Rejected: a flexbox engine such as `taffy` (more than the toolkit needs), intrinsic measurements (later, for equal-width rows).
- **D20. CPU rendering in a `winit` window on the main thread.** (The display list is implemented by `ui-toolkit`, and the window by `desktop-window`, whose decisions are in the Design Rationale of [`desktop`](../openspec/specs/desktop/spec.md). It pinned `softbuffer` 0.4.6, which shares `objc2` 0.5 with `winit` 0.30, and `tiny-skia` 0.12.0, rather than the 0.4.8 and 0.11 built here; windows lay text out with Inter's rounded advances while headless runs keep the fixed-advance metric of D21.) `winit` 0.30 (Apache-2.0), `softbuffer` 0.4 (MIT or Apache-2.0), `tiny-skia` 0.11 (BSD-3-Clause) and `fontdue` 0.9 (MIT, Apache-2.0 or Zlib) are pure Rust apart from platform bindings and were built together on macOS arm64 on 2026-10-18. The bundled font is Inter (SIL Open Font License 1.1, shipped with its licence). Software rasterization at 800×600 fits a frame budget and keeps build times and determinism; the display list lets a GPU backend replace it later. `prism run` already runs `main` on a thread of its own (for its stack size), and macOS requires the window's event loop on the main thread, so the CLI's main thread serves windows while the program thread composes. Rejected: `wgpu` with `vello` or `glyphon` (large dependency tree, GPU-dependent output), running programs on the main thread.
- **D21. Headless mode with text dumps.** (Implemented by `ui-toolkit`, the dump printing each node's modifier chain in order; see [`ui`](../openspec/specs/ui/spec.md).) A text dump of the laid-out tree is exact on every platform and reviewable in a diff, and the existing run-fixture runner already compares stdout under the allocation check; scripts target nodes by text so they survive layout changes. PNG screenshots are for people, since anti-aliasing differs across CPUs. Rejected: PNG golden images, a Prism-level UI test API now (it needs `prism test`; a later item).
- **D22. Handlers are closures owned by nodes.** `escaping` handler parameters (`references`, "Escaping Parameters Keep Function Values") move the closure, which owns its captures ("Closures That Escape Own Their Captures"), into the node, which drops it when replaced, freeing its environment (`execution`, "Owned Environments Are Freed Exactly Once"); the runtime calls it through its descriptor's slot, so reloaded code runs on the next click. Click on release over the pressed node, as desktop toolkits do. Rejected: a global handler table keyed by `NodeId`, press-time clicks. (Refined and implemented by `ui-toolkit` D23: a handler given through a modifier is moved into `prism-ui`'s handler table and owned by the node that claims it, so a `Copy` modifier can name it; events are dispatched one at a time with a pass after each, revising the batched pass planned here.)
- **D23. Hot reload recomposes the reloaded files' scopes.** (Implemented by `compose-hot-reload`, which refines it: a reload invalidates the nearest restart scope above every group of an affected composable body, those of reloaded units and of the files importing them, so non-skippable composables, content lambdas and edited helpers are covered; there is no forced pass, the pass after a reload compares every kept argument, and a scope whose composable's signature changed recomposes from its parent with its own slots reset; see the Design Rationale of [`compose`](../openspec/specs/compose/spec.md) and [`ui`](../openspec/specs/ui/spec.md).) Recomposing every restart scope of a reloaded file is simple and catches every changed body for the price of one frame; keys (D5) and fingerprints decide what state survives, and resetting a changed-type slot is the answer `codegen-aggregates` (D10, D21) left open for slot-table state. A closure whose captures changed gets a new slot because a stored function value with the old environment would otherwise run new code over the wrong layout, which `hot-reload` must also respect for function values outside compositions. Rejected: recomposing only bodies whose MIR hash changed (a later refinement), restarting the app, migrating state between layouts.
- **D24. Verification by scripted apps and measured frames.** (Implemented by `reactive-app-verification`, which states "zero GC pauses" as three measured properties, adds a 99th-percentile frame target and a startup target, and leaves the 16 ms window target to a check by hand; see the Design Rationale of [`example-apps`](../openspec/specs/example-apps/spec.md).) The counter and todo apps exercise state, lists, keys, text input, skipping and disposal; counting live cells, groups and nodes extends "no allocation outlives its owner" to the runtime's arenas. The timing targets follow the `codegen-core` benchmark's approach (a release build, the median of repeated runs). Rejected: verifying by hand in a window only.
- **D25. Out of scope for Milestone 2: future work.** Apart from `SideEffect`, nothing in this item is implemented, and each is a follow-up in [`ROADMAP.md`](../ROADMAP.md) beyond Milestone 2. Effects (`LaunchedEffect`, `DisposableEffect`; `SideEffect` was brought forward by `state-handles`, its D13, as the one way for composed code to act outside a pass before the toolkit's handlers), timers and animation, `derivedStateOf`, subcomposition and lazy lists, IME and text selection, accessibility, multiple threads, mobile targets and a GPU renderer. Each can be added without changing the decisions above.
- **Compile-time cost (audited 2026-10-19, when the user made fast compilation a primary criterion).** The transform is one pass over each body's elaborated MIR, once per body rather than per instance (D3, revised). Group keys are one hash per group from paths the pass already walks, with a per-construct counter for same-callee ordinals (D5). Stability is a marker lookup per parameter type (D9), never an inference over fields or other files. A closure descriptor's equality entry is one small function per closure that owns only `Copy` captures, a word compare for inline environments (`escaping-closures` D9), and equalities call per-type glue (D16, revised). The static state rules (D13, D14) are checks of the enclosing context's composable flag at each state access, linear in the body (implemented by `state-handles`). The bundled library is checked like any file and cached under the compiler version (D2), so a build pays for it once. Nothing here is whole-program except instance collection, which `monomorphization` keeps linear in the instances.
