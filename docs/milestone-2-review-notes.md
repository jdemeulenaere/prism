## Findings from the user's testing

| # | Finding | Status |
|---|---------|--------|
| F2 | Hot reload in a window: `reload: applied` is printed at once, but the window only shows the new code after a click or a focus change. **Cause (from reading `prism-ui/src/app.rs` and `prism-desktop/src/host.rs`):** the reload's wake-up makes a frame due, so the host returns `Frame` before the loop gets back to its reload point. The frame presents the old tree, then the reload is applied and recomposed, and nothing presents the result until the next input event. Headless fixtures hide it because their scripts always `dump` or `frame` after `wait reload`. | **Fixed (2026-10-20, A3):** a wake-up is `HostEvent::Wake`, which returns the loop to its reload point, and the window host makes a frame due after it |
| F3 | Toggling one item of the 1,000-item list recomposes all 1,000 rows. In a window, recomposition takes 6.65 ms median (target < 4 ms, met headless at 1.9 ms); input-to-present p99 is 15.2 ms (target < 16 ms, met). The small todo app is fast only because it has few rows. **Cause:** rows take `&Todo`, and a borrowed parameter is never stable (compose-architecture D9, compose-transform D7), so every row re-runs whenever the list state changes. **Why a window is 3.5× slower (investigated 2026-10-20, see F4):** the work is the same; the CPU is not. A person's clicks come about 100 ms apart, the program thread sleeps in between, and Apple silicon lowers the core's clock while it idles, so a burst of a few milliseconds runs mostly before the clock comes back up, with cold caches. Headless, the benchmark's script runs its toggles back to back on a fully clocked core. | Explained (F4); the work itself: see C2. **Fixed by `strong-skipping` (2026-10-20):** a toggle recomposes one row and the count: recomposition 0.010 ms back to back and 0.24 ms paced headless, 0.23 ms in a window (input to present 7.9 ms median, 9.3 ms p99). |
| F4 | Measured with `app_windows`'s `large` scenario (20 toggles at the window's pace, release build, M4 Pro) against its `large-headless` control. Recomposition median: window 6.2–7.3 ms, headless back to back 1.9 ms, headless with a 50 ms sleep before each script line 5.3 ms, window with one unrelated busy process holding the performance cores' clock up 2.0 ms. With that busy process, every window stage drops to its headless value: events 1.6 → 0.1 ms, display list 0.6 → 0.23 ms, raster 3.0 → 1.35 ms, input to present 12.9 → 3.7 ms median. A plain compute loop of 2 ms on this machine takes 3.3–3.8 ms after a 20–100 ms sleep. **Ruled out:** the Inter measurer (it is a per-size table, and recomposition never calls it; headless with sleeps shows the same slowdown with fixed metrics), the program thread's QoS (it is `default` both ways; raising it to `user-interactive` changed nothing, in the window or in the compute loop), the counting allocator (per-thread cells, same in both runs), and glyph cache misses (25 in total, none after the first frame). **Raster:** of its 3.0 ms (cold) median, drawing the list takes 0.65 ms (0.35 hot), copying into the surface 0.14 ms, and softbuffer's `present` 2.05 ms (0.9 hot): it wraps a freshly allocated, zeroed 800 × 600 buffer in a device-RGB `CGImage` and commits it to the layer, every frame. **No plain fix:** keeping a core busy wastes power and breaks the idle-CPU check, and QoS does not help. **Options (need a decision):** (a) nothing beyond C2/A1: once a toggle recomposes one row the burst is a fraction of a millisecond, cold or not; (b) pace `app_frame_timing`'s scripts (a sleep between events in the benchmark, or a `pause <ms>` script command) so its targets measure input at a person's pace; (c) a present path without the per-frame allocation and `CGImage` (an `IOSurface`-backed layer, or the display's colour space), a `prism-desktop` change. **Recommendation:** (a) now, with (b) when `strong-skipping` lands so its gain is measured as a person sees it; (c) only if the raster stage misses a target. | (b) **done** (`strong-skipping`, 2026-10-20): `pause <ms>` in event scripts, and `app_frame_timing` paces the todo inputs 100 ms apart; paced, a toggle's frame is 3.0 ms median and 6.0 ms p99 (its event dispatch alone 1.6 ms, 0.06 ms back to back), above the 4 ms p99 target, and typing's recomposition 2.2 ms median against 2 ms (follow-up of `strong-skipping` in `ROADMAP.md`). (c) open. |

Not reproduced since; possibly related to the agent's repeated test launches. | Open: watch for a recurrence; trace with `PRISM_WINDOW_TRACE` (temporary build) if it happens again |

## Agreed changes

| # | Change | Notes |
|---|--------|-------|
| A1 | **Strong skipping with provenance identity** (from C2; revised after the user's feedback, 2026-10-19). | No stability inference: every restartable composable can skip, as with Compose's strong skipping (user). `Copy` parameters compare by value. A borrowed parameter carries an identity the compose transform derives syntactically at the call site: address plus source version (a state cell's version; a top-level `val`; the parent parameter's identity passed down). A borrow of a local or temporary has none and always recomposes. Different identity means recompose, with no deep-comparison fallback and nothing cloned or kept (user: avoid expensive comparisons). A structural list change recomposes every row once; per-element stamps are a possible refinement (open). Replaces the kept-clone and kept-hash ideas. **Done (2026-10-20, `strong-skipping`):** composables taking `&T` are restart scopes kept by address and version (a state's version, renewed by every write; permanent for remembered and top-level values; the caller's for parts of its borrowed parameters; none for locals, which run in a replaceable group); the 1,000-item todo app recomposes one row per toggle, skips every row while typing, and reruns each row once when an item is added (`dump recompositions` sessions). Per-element versions stay open. **Reviewed and archived (2026-10-20, `openspec/changes/archive/2026-10-20-strong-skipping/`):** the review fixed a stale-UI bug (an element of a top-level list chosen by an index was trusted as static) and two restarts reading a dead frame (version words depended on a parameter's referent and mutability, so a lambda given for a generic or a `&mut` function type took other words than its caller passed; every borrow parameter now takes one). The paced frame targets missed on F4's clocked-down core are follow-ups in `ROADMAP.md`. |
| A2 | ~~Owning state fields through a separate `OwnedState<T>` type~~ | **Superseded by A2′** (2026-10-20): `MutableState<T>` itself becomes the owning state object, so there is no `OwnedState` type. Kept only as history; implement A2′. |
| A2′ | **Rethink `MutableState` as an owning state object, as in Compose** (proposed 2026-10-19 after the user asked whether `MutableState` could simply be a state holder; would replace A2). | `MutableState<T>` becomes a move-only owning object (contents in a stable runtime block, freed on drop), usable directly as a struct field (`val done: MutableState<Boolean>`). `remember` may keep owned values (dropped when their group leaves; revises compose-architecture D8). Escaping closures that capture a state place capture an automatic generational `Copy` handle (syntactic rule; a stale handle is a located runtime error). This amends system invariant 6 (state handles become an implementation detail) and dissolves most of state-handles D5 (`read`/`update`/`edit`, E4033), since owned state borrows normally. Snapshots: observation only for now; snapshot creation and multi-threading later. **Agreed by the user (2026-10-20), invariant 6 amendment included; replaces A2.** **Done (2026-10-20, `owned-state`, reviewed and archived in `openspec/changes/archive/2026-10-20-owned-state/`):** state objects are owned and move-only, compared by identity; a state's value is a place borrowed normally, with run-time flags held by guards outside composition; `remember` keeps owned values (a `&T` of a non-`Copy` one); dropping a state retires it, freed at the end of the next pass; a removed group releases its node, then its restart function, then its slots; the library declares weak capture with `capture fun` (L5); the todo app's `Todo` holds `done: MutableState<Bool>`, and a toggle recomposes 2 scopes. |
| A2‴ | **No stale-state errors in UI code** (follow-up to A2′: the user asked whether its weak handles allow use-after-free). | They never read freed memory (generational check), but a handler could hit a stale-state runtime error. Proposed rules: (R1) a group's nodes and handlers are released before the state it owns, as a spec guarantee; (R2) dropping a `MutableState` retires it, and it is freed at the end of the next composition pass, by which time every composable that received the removed data has recomposed (A1's provenance identity changes), so its handlers were replaced; (R3) implicit weak-handle captures are allowed only for closures passed to composition-bound parameters (UI handlers stored in nodes, a parameter kind distinct from plain `escaping`); elsewhere, an explicit weak reference whose access is nullable (`count.weak()`, `ref.get()?.value`). The generational check stays as a safety net. Reference counting handlers was rejected (hidden ARC). **Agreed by the user (2026-10-20).** **Done (2026-10-20, `owned-state`):** closures given to `attached` parameters (the toolkit's handlers, `composition`, `setContent`, `SideEffect`) capture states weakly, and the borrow checker keeps those states borrowed while a composition holding them is used (`E5005`/`E5006` instead of a stale state at run time, `E5010` for attached values escaping elsewhere); elsewhere `count.weak()` and `ref.get()?.value`. Forwarding an attached handler from inside a nested content lambda is still rejected (open, C5 below). The review closed two more ways for code that owns a composition to drop a state its content shows (a helper setting a composition's content through `&Composition`, and a composition held in a field or list given such content), and a use after free through a borrow of a state's value outliving its guard. |
| A4 | **The standard and compose libraries as ordinary Prism code** (user, 2026-10-20: "as much as possible ... normal prism code that is imported like any other code"). | Proposed minimal core. Compiler: scalars, `T?`, `&T`, function types, string literals as primitive static text, `compose fun` and its transform, `external fun`, and one composer-access primitive. Language additions so the rest can be Prism: (L1) Kotlin-style `operator fun` conventions; (L2) custom drop and clone hooks; (L3) an `unsafe` memory layer for library containers; (L4) `vararg`; (L5) library-declared weak capture (A2′/R3). Native through `external`: allocator, panics, output, window, raster, fonts, input; the slot table and state runtime for now; layout for now (later a Compose-style `Layout` and `MeasurePolicy`). Staging: L1/L2/L4 plus compose state and runtime APIs in Prism → L3 and containers → layout. Location: superseded by the agreed follow-up (a) below, a top-level `library/` directory imported as `/prism/...` from any workspace. **User decisions (2026-10-20):** no `unsafe` for now, so `List`, `String` and `Heap` stay Rust-backed (L3 dropped); explicit imports everywhere, no prelude, to be revisited after seeing the result; layout in Prism this round, as the last item. **Follow-ups agreed (2026-10-20):** built-in type names (`Int`, `Double`, `Bool`, `Char`, `String`, `Unit`, `Nothing`, `List`, `Heap`, `Range`) and the members of built-in types stay in scope everywhere; every function (`println`, `listOf`, `map`, `remember`, `mutableStateOf`, `Column`, ...) needs an explicit import. Location (a): `/prism/...` keeps resolving to the library from any workspace, but its sources move to a visible top-level directory (e.g. `library/prism/...`) as ordinary compilation units, with no prelude and fewer intrinsics. |
| A2b | **Path captures** (needed by A2′ for Kotlin-like handlers). | `onCheckedChange = { todo.done.value = it }` captures the path `todo.done` (with A2′, as an automatic generational handle to the owned state) instead of the borrowed `todo` (E5007 today), like Rust 2021's disjoint captures; decided syntactically, at no inference cost. **Done (2026-10-20, `path-captures`, archived in `openspec/changes/archive/2026-10-20-path-captures/`):** closures capture paths, owning closures copy the `Copy` paths no later write could change, and the todo example's handlers capture `todo.id` directly. |
| A3 | **Hot reload refreshes the window without input** (F2): plain fix. | A wake-up returns to the loop's reload point before a frame is built (or applying a reload makes a frame due), with a window test. **Done (2026-10-20):** the window host turns a wake-up into `HostEvent::Wake` and then a frame; tested by `a_reload_is_presented_without_input` (`prism-desktop`) and the `watch-reload` window scenario, which now checks the presented text. |
