# Prism Agent Guidelines (The Elephant & Goldfish Operating Manual)

Welcome to the **Prism** language repository. This document serves as the primary onboarding directive for AI agents and human contributors.

---

## 1. The Core Philosophy: The Elephant & Goldfish Model via OpenSpec
This project strictly follows the **Elephant-Goldfish model** (see [Rensin, 2024](https://drensin.medium.com/elephants-goldfish-and-the-new-golden-age-of-software-engineering-c33641a48874)) using [OpenSpec](https://github.com/Fission-AI/openspec):
- **The Elephant (Durable Memory)**: All architectural invariants, grammar specifications, decisions, and roadmaps are permanently documented in [`openspec/specs/`](openspec/specs). When starting a task, **always consult the Elephant specs** to ensure alignment.
- **The Goldfish (Ephemeral Execution)**: Tasks are proposed and executed via [`openspec/changes/<change-name>/`](openspec/changes) work packets:
  - `proposal.md`: Motivation and scope boundary.
  - `design.md`: Technical approach, trade-offs, and design decisions (eliminates separate ADR drift).
  - `tasks.md`: Atomic, test-driven checklist.
  - `specs/`: Delta specifications with concrete scenarios (WHEN/THEN).
  - Once verified, the change is archived to `openspec/changes/archive/` and its delta specs merge into `openspec/specs/`.
- **Change packet or plain fix?** Not every change needs a change packet:
  - **Plain fix** (no change packet): the code is wrong and the spec already states, or obviously implies, the correct behaviour. Crashes always count. Commit the fix with a regression test that runs real `.prism` source (not a hand-built AST), named after the spec scenario it protects. If the spec was silent on that case, add the missing scenario to the main spec in the same commit; that pins down existing intent rather than changing behaviour.
  - **OpenSpec change**: the fix needs a decision someone could reasonably disagree with. That covers new semantics, a grammar rule, a new or reassigned error code (beyond taking the next free code for a new error kind, per [`diagnostics`](openspec/specs/diagnostics/spec.md)), changing an existing scenario, or an architectural choice.
  - Quick test: if you'd want to review the *design* before seeing code, propose a change; if you'd only want to review the *diff*, make a plain fix.
- **OpenSpec Workflows / Slash Commands**:
  - `/opsx-propose "change-name"`: Creates and populates the change packet.
  - `/opsx-apply`: Executes the tasks against the spec.
  - `/opsx-archive`: Merges deltas and archives the change.
  - `/opsx-sync`: Syncs delta specs from a change into main specs without archiving.
  - `/opsx-explore`: Interactive thinking partner for clarifying ideas before drafting specs.
  - `/opsx-update`: Revises existing planning artifacts to reconcile changes.
  - Claude Code uses a colon instead of a dash (`/opsx:propose`, `/opsx:apply`, ...); its skills and commands live in `.claude/`, while `.agents/` holds the Antigravity copies. Refresh both with `openspec update`; to change which tools are generated, run `openspec init --tools claude,antigravity`.

## 2. Architectural Invariants (Non-Negotiable)

Every code, grammar, or compiler change must uphold these. The normative text, with scenarios, is [`openspec/specs/system-invariants/spec.md`](openspec/specs/system-invariants/spec.md); keep this list as a one-line summary of it.

1. **Single-file compilation units with explicit export boundaries**: each `.prism` file compiles independently. Default visibility is `private`; `package` is visible within the package directory, `public` across packages. `public` and `package` declarations must declare explicit parameter and return types.
2. **Zero build files, zero marker files**: the workspace root comes from matching the file's path to its `package` declaration. Root-anchored imports use a leading slash (`import /core/fmt`), sibling imports a plain name (`import doo`).
3. **Deterministic hermetic builds and compilation avoidance**: a file's artifact depends only on its content, its direct imports' ABI hashes, the compiler version and the target. Phase 1 extracts ABI hashes, Phase 2 checks bodies; editing a non-generic body causes zero downstream recompilation.
4. **Kotlin-like syntax without ambiguity**: `fun`, `val`/`var`, `struct`, `enum`, `when`, `if` and `T?`, parsed deterministically.
5. **Zero-cost memory safety**: zero GC, zero hidden ARC, no lifetime annotations. Single-owner values, `Heap<T>` for recursion, stack-scoped borrows with elision, typed handles for graphs.
6. **First-class compose and hot reload**: `compose fun` is a native modifier; slot-table handles (`State<T>`, `NodeId`) are `Copy` IDs; the Tier 1 JIT swaps composable bodies while keeping UI state.

In code comments and diagnostics, cite an invariant by name ("the zero-marker invariant"), not by number.

## 3. Key Reference Documents ("The Elephant")

What is implemented and what is planned live in different places. Never treat a planned design as a description of the code.

- **Implemented behavior: [`openspec/specs/`](openspec/specs)**, the source of truth for what the compiler does today. Each spec's `## Design Rationale` section records why past decisions were made:
  - [`package-resolution`](openspec/specs/package-resolution/spec.md): Zero-marker root discovery, import resolution, package scanning, and the reserved root package `prism` (`E1008`) that names the bundled library.
  - [`syntax`](openspec/specs/syntax/spec.md): Concrete grammar, tokens, and language constructs, the `escaping` parameter modifier, string templates (`$name`, `${expression}`, `\$`) and their tokens, closure headers (`{ -> }` distinct from none) with `it` an ordinary identifier, function types with a receiver (`T.(A) -> R`, `mut T.() -> R`) and `context(name: T)` declarations, `intrinsic struct` declarations, and the comment-collecting lexer mode tools use.
  - [`type-system`](openspec/specs/type-system/spec.md): Bidirectional typing, Nothing bottom type, nominal types, infinitely sized types (`E4023`), `Heap(value)` construction and invariant boxes, the string members and `toString()` (intrinsics of `/prism/core`), the text forms of string template parts (`E4026`) and of `print` arguments, function values converting only without changing representation, `escaping` parameters in function types, a closure's implicit `it` (when it has one, shadowing, `E4001` and `E4004` for closure parameters), and function types with a receiver: their in-place conversion to plain function types, lambdas with a receiver and the three ways to call a receiver function value, and default values checked outside composable contexts (`E4008`), `MutableState<T>` converting to `State<T>`, and companion values (a struct and a top-level `val` of one file sharing a name).
  - [`compilation-and-abi`](openspec/specs/compilation-and-abi/spec.md): Phase 1 ABI extraction, the deterministic ABI hash (one hash, covering no body), generic signatures and marker parameters, the definitions of reachable types, the generic records instances are built from and their Monomorphization Hashes, what an instance may depend on, instances planned per program from file summaries and keyed by their record and type arguments, code generation avoidance, and `escaping` flags in the ABI.
  - [`ownership`](openspec/specs/ownership/spec.md): `Copy` and `Clone` markers, explicit `.clone()`, whole-value moves (taking a value apart moves it whole; no partial moves), immutable top-level declarations, the borrow checker's use-after-move and uninitialized-read rules, closures never moving their captures, closures that capture by value moving or copying the binding and the captures they cannot take (`E4028`), and moving a box's contents out with `unbox()` and consuming receivers.
  - [`patterns`](openspec/specs/patterns/spec.md): `when` patterns and destructuring declarations: constructor patterns, wildcards, `val`/`var` bindings, guards, alternatives, binding modes from the subject's type, patterns through boxes, exhaustiveness with a named missing value, and `val (name, email) = user`.
  - [`loops`](openspec/specs/loops/spec.md): `while`, `do`/`while` and `for` loops (over a `Range` or a `List`), and `break`/`continue`, and how they run.
  - [`collections`](openspec/specs/collections/spec.md): The built-in growable `List<T>`: its reserved name and markers, `listOf` and the members, declared as intrinsics of `/prism/collections`, and their precedence over extensions, the higher-order helpers written in Prism (`map`, a consuming `filter`, `joinToString`, ...), elements as places (`xs[i]`), `for (x in xs)` binding `&T`, element equality, and the borrow rules for elements and iterated lists.
  - [`references`](openspec/specs/references/spec.md): Implicit borrows at argument sites and of method receivers, copy-out, writing through references and into boxes (`*h = v`), reborrows, the borrowed-nullable view and boxes lending their contents; and the borrow checker's exclusivity rules: non-lexical borrows, conflicts, disjoint fields, closure captures; and which captures a closure owns (decided from the source: closures that escape or outlive a captured binding), `escaping` parameters and escaping function values holding no borrow (`E5007`); and the four lifetime elision rules: what a call's result keeps borrowed and what a body may return a borrow of; and template parts borrowed until the template is built; and how receivers of function values and context arguments are borrowed, and receiver function types eliding as their plain forms; and borrows of a state's value holding no loan, and values written into a state escaping.
  - [`extension-functions`](openspec/specs/extension-functions/spec.md): Methods as extension functions: declaration, resolution through the file and its imports, implicit `this` (the innermost receiver only, also in lambdas with a receiver), context parameters and a call's context (`E4034`), extensions differing only by context, and safe-navigation calls.
  - [`generics`](openspec/specs/generics/spec.md): Type parameters on functions, extensions, structs and enums: `Copy`/`Clone` bounds, move-only unbounded parameters, explicit and inferred type arguments, borrow-free type arguments, invariant generic types and generic extension receivers. Checked once at the declaration and run as instances; `?:` on a type parameter tests for null, and polymorphic recursion and non-regular generic types, through boxes and lists, are rejected (`E4027`, `E6004` across files).
  - [`typed-tree`](openspec/specs/typed-tree/spec.md): The type checker's output: resolved bindings and declaration paths, a type on every node, explicit coercions, moves, copies and borrows, normalized calls, captures with their modes (borrowed, moved, copied) and why a closure owns them, templates, list operations as built-in calls, elements as index nodes, how a `for` loop iterates, a closure's implicit `it` as a parameter local, state places and state built-ins, and the `prism dump-typed-tree` command.
  - [`mir`](openspec/specs/mir/spec.md): The control-flow graph lowered from each typed file: typed locals, places, storage, drops, temporary scopes, branches, calls, default generators (borrowing only what their default reads), closures (built from moves and copies of owned captures), function names and variant constructors as adapter closures, templates, elements as index projections, list loops walked by index, list operations as built-in calls, instances of generic bodies (substituted and flattened, with their closures), the region markers of composable bodies and the composed MIR of the compose transform (composer and change words, group keys, kept arguments, restart closures, `remember` windows and side effects), state operations as calls, node groups for `Node` and `LeafNode`, unit properties as constructions, and the `prism dump-mir` command with `--instances` and `--composed`.
  - [`code-generation`](openspec/specs/code-generation/spec.md): The Tier 1 Cranelift backend: per-file code units, one code unit and slot per instance of a generic, symbols, calls through the function table, scalar representation, layouts of strings, structs, enums, nullables, boxes and lists (`{ pointer, size, capacity }`, growing by doubling, bounds-checked elements), string literals as static data, the runtime allocator, drop, clone, equality and index-of glue that checks the stack, templates as one runtime call with one allocation, function values as a descriptor and an environment (closure code with its own slot, borrowing environments in the creating frame, owned environments in one allocation or inline in one word, calls through the descriptor's slot, drop entries and `#drop-environment` functions), composable signatures, composer operations as compose runtime calls, slot type records and equality glue for kept values, four-word descriptors with environment equality and duplicate entries, intrinsic structs as one handle word, passing aggregates by address, what it rejects (`E6001`), compiled units as relocatable artifacts defined through one path whether fresh or cached, stack checks as reload points, slots resolved by symbol and top-level storage in the program's value table (`hot-reload`), state handles as one word and state operations as located calls of the compose runtime, `prism-ui`'s entry points and intrinsic equality entries (`HandlerId`), `prism dump-clif` (with `--instances`) and `prism dump-layout`.
  - [`execution`](openspec/specs/execution/spec.md): Running a program with `prism run`: the entry point, exit statuses, `print`/`println` output, `Int` and `Double` arithmetic, runtime errors, top-level value initialization, struct, enum, nullable and box values (copies, borrows, equality, `when`, `?.` and `?:`), strings (concatenation, equality, `length`, characters, `toString()`, templates), lists (building, indexing, growing, removing, iterating, comparing, cloning and freeing their elements exactly once, index errors, the million-adds target), generic code (drops and clones of type-parameter values, flattened nullable arguments, runtime errors in an instance), closures and function values (captured variables read and written in place, closures that own their captures kept past their frame and freed exactly once, function names and variant constructors as values, function values held in structs, nullables and top-level values), freeing values where their owner's scope ends, cloning, `--check-allocations` (with undisposed compositions, program state cells freed first), the located state errors, runs from cached code behaving as cold ones, `--no-cache` and `--explain-cache`, the `--watch` and `--edits` options and a runtime error under watch ending only the run, `--headless` and `--events` with their script errors, `--screenshot` and its errors, live groups, slots, state cells and nodes in the allocation check, `--frame-stats` and its counting allocator, and the startup target.
  - [`standard-library`](openspec/specs/standard-library/spec.md): The Prism source shipped in the executable under the reserved root package `prism` (`/prism/core`, `/prism/collections`, `/prism/compose/runtime`, `/prism/system`, `/prism/composer`), the prelude and how its names and extensions are found last, `external fun` runtime entry points and `intrinsic` declarations, `intrinsic struct`s included (library-only, `E3002`), the intrinsic catalog (`E4029`), intrinsic extensions as members, writable `intrinsic var` properties, the state declarations of `/prism/compose/runtime`, the UI modules outside the prelude and their intrinsics (`NodeId`, `HandlerId`, `Node`, `LeafNode`, `runApp`, `Int.dp`, `Int.sp`), `exitProcess`, and the library's own checks.
  - [`compose`](openspec/specs/compose/spec.md): Composables and how they run: owned `Composition`s (`composition`, `setContent`, `recompose`, `dump`, disposal on drop, `E4030`), a group per composable body, keys from declarations and source structure, groups for branches, loops and composable `when` tests, call-site groups in loops with a `continue`, `remember` (with keys) and `key`, stable parameters, change bits, skipping and restart scopes, `currentRecomposeScope`, composable lambdas, the `/prism/compose/runtime` prelude; state: `State<T>` and `MutableState<T>` handles, `mutableStateOf`, `.value` (a copy, or a place in composable contexts), `read`, `update` and `edit` with run-time borrow flags, reads registering their restart scope, writes invalidating it unless equal, state read-only during composition (`E4031` to `E4033` and run-time errors), cells owned by their `remember` slot, composition or the program, stale handles and `SideEffect`; hot reload of composables: the scopes a reload recomposes (affected bodies by body key), kept and reset state, kept arguments compared after a reload, and retired restart scopes; and the composition runtime `prism-compose`: compositions and passes, the slot table of keyed groups and typed or word slots, removals deferred to the end of the pass and their release order, restart scopes and invalidation in tree order, node groups through an `Applier` and the built-in node tree, handle validation and `composition misuse` errors, the protocol module `/prism/composer`, dumps, and the runtime's costs.
  - [`ui`](openspec/specs/ui/spec.md): The UI toolkit: the `prism-ui` crate and the toolkit modules `/prism/compose/ui`, `/prism/compose/foundation`, `/prism/compose/layout` and `/prism/compose/material3`, split and named as Jetpack Compose's artifacts, with Compose's signatures; `runApp` and its frame loop; ordered `Modifier` chains of plain data (16 elements at most), `Dp`/`TextUnit`, colours, shapes, arrangements, alignments and scoped `weight`/`align`; constraint layout and fixed-advance text metrics; the node tree, nodes owning their values and the handler table behind `HandlerId`; the display list and content colours; clicks, toggles, focus and typing; headless runs, event scripts (text and kind targets, with `edit` and `wait reload` under `--watch`) and dumps; the frame loop's reload point, handlers and errors after a reload, and the UI reload latency target; frames as `--frame-stats` measures and reports them; `ui misuse` errors; and the toolkit's costs.

  - [`desktop`](openspec/specs/desktop/spec.md): Apps in a native window: the `prism-desktop` crate behind `prism-cli`'s default `window` feature, the main thread serving windows while the program keeps its thread, lazy start, window lifecycle and closing, HiDPI scaling, CPU rasterization and its determinism, the bundled Inter font and the window's text metrics without shaping, redraws on change only, input mapping, display errors, watch sessions with windows, the window's raster and input-to-present lines in frame statistics, and the window's costs.
  - [`example-apps`](openspec/specs/example-apps/spec.md): The reference apps under `examples/` (the counter, the todo list and its 1,000-item screen, the toolkit tour): what each must do, the sessions beside them that `example_app_sessions` runs under the allocation check, their hot-reload sessions, the rule that every example checks, formats and runs, and their frame, allocation and startup targets.
  - [`build-cache`](openspec/specs/build-cache/spec.md): The per-user, content-addressed build cache through which `prism check` skips unchanged files and `prism run` also loads unchanged units' and instances' code: check entries with file summaries, generic records by their hash, code entries keyed with the target identity, the executable's recorded hash, `--no-cache` and `--explain-cache` (instances listed once per program).
  - [`formatting`](openspec/specs/formatting/spec.md): `prism fmt`, its canonical layout, comment preservation, templates printed as written, `escaping` and closure headers kept as written, and the meaning and idempotency guarantees.
  - [`diagnostics`](openspec/specs/diagnostics/spec.md): The catalog of every compiler error code. A change that adds an error adds its code here.
  - [`system-invariants`](openspec/specs/system-invariants/spec.md): The 6 non-negotiable invariants. These are design constraints, so they also cover subsystems not built yet.
- **Planned design: [`docs/architecture.md`](docs/architecture.md)**: parallel Phase 2 compilation, Tier 2, and the rest of the memory model (typed handles for graphs); its compose section is implemented and keeps the engine's design notes, with what lies beyond Milestone 2. A change that implements an item moves its requirements into `openspec/specs/` as delta specs and removes them from this document.
- **Progress: [`ROADMAP.md`](ROADMAP.md)**: current phase and milestones. [`README.md`](README.md) is the high-level vision.
- **History: `openspec/changes/archive/`**: completed change packets. Historical only and never authoritative: their delta specs and task lists are snapshots that may since have been superseded. Do not read them for current behavior. Consult them only to research why a past decision was made.

## 4. Current Milestone & Focus
- **Milestone 1** (complete): Minimal Viable Bootstrap Compiler in Rust (`prismc` / `prism` CLI).
- **Milestone 2** (complete, 2026-10-19): First-class Jetpack Compose UI engine, reactive tree runtime, and native hot-reload framework. The decisions taken on the user's behalf on the way are summarized for review at the top of [`docs/decisions-for-review.md`](docs/decisions-for-review.md), with the checks that still need the user.
- **Milestone 3** (current focus): Self-hosting compiler written in Prism itself, with Phase 5's Tier 2 backend and LSP ([`ROADMAP.md`](ROADMAP.md)).

When writing or reviewing code, always ensure existing tests pass and new language features include executable test fixtures.

Naming: spell out new identifiers in full words (`Statement`, not `Stmt`); don't abbreviate for brevity's sake. Existing abbreviated names (`Expr`, `BlockExpr`, ...) stay until a change deliberately renames them.
