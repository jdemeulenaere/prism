# Prism Diagnostic Codes

## Purpose
The diagnostics specification is the single catalog of compiler error codes. Each code identifies one kind of error across all stages (resolution, parsing, ABI extraction, type checking and borrow checking), so tools and tests can key on codes instead of message text. The other specs reference these codes in their scenarios; this spec lists them all in one place.

## Requirements

### Requirement: Stable Diagnostic Codes
Every error the compiler reports MUST carry a code from the catalog below. A code MUST keep its meaning once assigned, and a retired code MUST NOT be reused.

#### Scenario: Rendered diagnostic header
- **WHEN** `prism check` or `prism run` reports an error
- **THEN** the diagnostic starts with `error[<code>]: <title>`, followed by the source location when one is known

#### Scenario: Syntax error location and lexer message
- **WHEN** `prism check` reports an `E2xxx` error, including one in an imported file
- **THEN** the diagnostic points at the error's own line and column, and a lexer error shows the lexer's message (`Unknown escape sequence '\q'`) rather than the parser's view of an error token

#### Scenario: Code range identifies the stage
- **WHEN** a diagnostic is reported
- **THEN** its code falls in the range of the stage that produced it: `E1xxx` resolution and I/O, `E2xxx` lexing and parsing, `E3xxx` Phase 1 ABI extraction, `E4xxx` Phase 2 type checking, `E5xxx` Phase 2 borrow checking, `E6xxx` code generation and the program's entry point

#### Scenario: New error kind gets a new code
- **WHEN** a change introduces a new kind of error
- **THEN** it takes the next unused code in its stage's range, adds it to this catalog, and does not reuse a retired code

#### Scenario: Runtime errors carry no code
- **WHEN** a running program raises a runtime error (see `execution`)
- **THEN** it is reported as `panic: <message>` with its location, without an `error[<code>]` header, because it is not a compiler error

### Requirement: Diagnostics Show Related Locations
When a diagnostic has a label for its primary location or related locations, such as where a used value was moved, the CLI MUST render the primary location's snippet with its label, then each related location in source order with its own location line, snippet and label, then the diagnostic's notes and help lines.

#### Scenario: Rendered related location
- **WHEN** `prism check` reports an `E5001` for `fun take(s: String) {}` and `fun f(s: String) { take(s); take(s) }`
- **THEN** after the header, the location and snippet of the second `s` labelled "value used here after move", it prints the location and snippet of the first `s` labelled "value moved here", then a `note` line and a `help` line

### Requirement: Unresolved Library Names Suggest Their Import
When a bare name or a type named in an annotation (`E4001`), or a member or extension (`E4006`), is not found, and a public declaration of that name in a library module would be found after importing it, the diagnostic MUST carry one help line per such module naming its import (`import /prism/core`). An extension MUST match only when its receiver type constructor is the receiver's, a library type, or a type parameter. A name no library module declares MUST get no such help.

#### Scenario: An unimported library function
- **WHEN** a file without imports declares `fun main() { println(1) }`
- **THEN** `prism check` reports `E4001` for `println` with the help line `'println' is declared by the library module '/prism/core': add 'import /prism/core'`

#### Scenario: An unimported library extension
- **WHEN** a file without imports declares `fun f(xs: &List<Int>): Int = xs.sumOf { x -> x }` and `fun g(n: Int): Int = n.sumOf { x -> x }`, and another declares its own `struct Composition(val n: Int)` and `fun h(c: &Composition): Bool = c.recompose()`
- **THEN** the `E4006` for `sumOf` in `f` carries help naming `import /prism/collections`, and those in `g` and `h` carry none, since no library module declares `sumOf` on `Int` or `recompose` on the file's own `Composition`

#### Scenario: A name the library does not declare
- **WHEN** a file without imports declares `fun main() { printn(1) }`
- **THEN** `prism check` reports `E4001` for `printn` with no help naming an import

## Catalog

### E1xxx: Resolution and I/O (`crates/prism-resolver`, `crates/prism-cli`)

| Code | Name | Meaning |
|---|---|---|
| `E1000` | `Io` | A file or directory could not be read, or a `prism check` target does not exist. |
| `E1001` | `PackagePathMismatch` | The declared `package` does not match the file's directory path, including a case-only mismatch or more package segments than directories. |
| `E1002` | `FileNotFound`, `LibraryImportNotFound` | An import targets a file that does not exist with the exact casing on disk. Also an import of the bundled library (`/prism/<module>`) naming a module it does not have, and an import of a library file that names anything but a library module (`standard-library`). |
| `E1003` | `PackageHeterogeneity` | Files directly inside one directory declare different packages. |
| `E1004` | `InconsistentWorkspaceRoot` | A dependency resolves to a different workspace root than the entry file. |
| `E1005` | `WorkspaceBoundaryViolation` | An import, entry file or scanned file resolves outside the workspace root, for example through a symlink. |
| `E1006` | `InvalidImportPath` | A file imports itself, or a sibling import has more than one segment. `.` and `..` segments are rejected earlier by the parser (`E2001`). |
| `E1007` | (retired) | Cyclic dependency. Retired by `fix-cli-workspace-audit`, which allowed mutually recursive imports. Do not reuse. |
| `E1008` | `ReservedPackage` | A workspace file declares the package `prism` or one below it (`package prism.ui`), which names the bundled library (`standard-library`). Help suggests renaming the package. |

### E2xxx: Lexing and parsing (`crates/prism-lexer`, `crates/prism-parser`)

| Code | Name | Meaning |
|---|---|---|
| `E2001` | syntax error | The lexer produced an error token or the parser rejected the source, including an assignment or compound assignment (`x += 1`) used as a value and the reserved `++` and `--`, a function without a body that is neither `external` nor `intrinsic`, a body on one that is, and an `intrinsic struct` with fields or a block or an `external struct` (`compose-transform`). The parser stops at the first error. Also `attached` before a type that is not a function type, outside a parameter's type or together with `escaping`, and `capture` without `intrinsic`, without a receiver or with `compose`, `mut` or `consuming` (`owned-state`). Also a second `vararg` parameter, a default value, `escaping` or `attached` on a vararg, and `vararg` on a struct's field, a closure, context or function-type parameter (`vararg`). Also an extension property without `intrinsic` that has no getter (the message says that an extension property has no stored value), an initializer (help suggesting `get() = ...`), `var`, `compose` or a receiver mode before it, or a type parameter that does not occur in its receiver type (named), and an `intrinsic` property with a getter (`core-library-in-prism`). Also a struct field with two visibility modifiers, a repeated one or one not followed by `val` or `var`, and a visibility modifier on an enum payload (`field-visibility`). Also an `@` not directly followed by a name, an annotation with arguments, and an annotation anywhere but before a top-level declaration (`compose-library-in-prism`). |
| `E2002` | `NestingTooDeep` | Expressions or types nest deeper than 256 levels, counting each operator of a left-associative chain such as `a + a + ... + a` as one level. |

### E3xxx: Phase 1 ABI extraction (`crates/prism-abi`)

| Code | Name | Meaning |
|---|---|---|
| `E3001` | `MissingExplicitReturnType`, `MissingExplicitVarType` | An exported declaration lacks a type required for ABI extraction: an expression-bodied `public`/`package` function without a return type, or an exported top-level variable without a type. |
| `E3002` | `LibraryOnlyDeclaration` | A workspace file declares something `external` or `intrinsic`, or writes an annotation (`@Keeper`, `compose-library-in-prism`), which only the bundled library may (`standard-library`). Reported in Phase 1 at the first such modifier or annotation's `@`, with help saying so. |

### E4xxx: Phase 2 type checking (`crates/prism-typechecker`)

| Code | Name | Meaning |
|---|---|---|
| `E4001` | `UnresolvedSymbol`, `UnresolvedTypeName`, `ThisOutsideExtension`, `UnboundPatternName`, `UnresolvedImplicitParameter`, `OuterReceiverName` | An identifier is not found in any enclosing scope or imported ABI, or `this` is used outside an extension function and every lambda with a receiver. A bare name found only on an outer receiver, a field or extension of an enclosing extension's or lambda's receiver that the innermost lambda with a receiver hides, gets help naming that receiver and suggesting a binding of it before the lambda (`OuterReceiverName`, `receiver-lambdas`). An unbound `it` gets help saying why the innermost closure has no implicit `it` (it declares its parameters, its expected type has none, or it has no expected function type) or, outside closures, what `it` names (`implicit-it`). A bare name in a pattern that resolves to nothing gets help suggesting `val name`, since a binding needs `val`. An extension is never found by its bare name, except on the implicit receiver of an extension body. Also (`BuiltinFunctionAsValue`) the built-in box constructor `Heap`, which can only be called, named without a call, and the built-in type `List` used as a value or called, whose help names `listOf` (`collections`). A library module that uses a name of another library module without importing it gets `E4001` too, since no file sees a library module it does not import (`standard-library`). A name a library module declares publicly gets one help line per such module naming its import (`'println' is declared by the library module '/prism/core': add 'import /prism/core'`), and an annotation naming a library module's public struct or enum without its import is `E4001` (`UnresolvedTypeName`, "unresolved type") with that help, where other unknown type names stay opaque (`explicit-library`). |
| `E4002` | `TypeMismatch`, `OperatorMismatch`, `TypeNameAsValue` | An expression's type is not assignable to the type expected by an annotation, assignment, operator operand or default value (return and argument sites have their own codes), including implicit numeric widening and `null` for a non-nullable type; a compound assignment's operator does not apply to its target's and value's types (`s -= "a"`, `n += 1` for `n: Int?`), or it would re-point a `var` reference binding (`r += 1`); or a struct or enum name is used as a value. Also indexing a value that is neither a `List` nor a `String`, a `for` loop over anything but a `Range` or a `List<T>`, and `==` on lists or `contains`/`indexOf` on a list whose element type mentions a type parameter (`collections`). Also (`MissingOperatorFunction`, `operator-conventions`) an operator use the built-in operator does not serve and no `operator` function of the receiver's type does: arithmetic, prefix, ordering and membership operators, compound assignments (whose operator function must also return the target's type), indexing without `get`, indexed assignment through a `set` not declared `operator`, and a `for` loop over a type whose `iterator`, `hasNext` and `next` are missing or disagree on the cursor type; the help names the declaration to add, says to mark an existing function `operator`, suggests a safe call (`a?.plus(b)`) for a nullable receiver, or names the library module declaring the function to import. |
| `E4003` | `ImmutabilityViolation` | Reassigning a `val` (also by a compound assignment such as `n += 1`), assigning a `val` field, mutating a field of a `val` instance, taking `&mut` of a `val` (also one holding a `&mut T`, which is reborrowed by passing it instead), or writing through a shared `&` borrow (`*r = v`). Also the receiver of a `mut fun` call that is not a mutable place (a `val` binding, a `val` field, a place reached through a shared `&`), including `this` in a `fun` or `consuming fun`. Also writing an element of a list that is not a mutable place (`xs[0] = 1` for `xs: &List<Int>`), and a mutating list member on one (`ys.clear()` for a `val ys`), whose help says that a list is changed through a `var` or a `&mut`, and writing through the variable of a loop over a list borrowed shared, whose help suggests `for (x in &mut xs)` (`collections`). Also an assignment or compound assignment of the `value` of a `State<T>`, which is read-only, with help naming `MutableState<T>` (`state-handles`). Also (`operator-conventions`) a write, mutable borrow or `mut fun` receiver of an element reached through a `get` operator when the indexed type has no `mut` `get` (help naming `operator mut fun T.get(...): &mut E`) or the indexed value is not writable, a call of a value whose `invoke` has a `mut` receiver on a value that is not a mutable place, a compound assignment through an operator function on a `val`, and `for (x in &mut y)` over a type without a `mut` `next` (help naming it); a field write through a loop variable of a shared iteration gets help suggesting `for (x in &mut y)`. |
| `E4004` | `CallSignatureMismatch`, `ArgumentTypeMismatch`, `ClosureParameterCount`, `MissingFunctionValueReceiver` | Wrong argument count, a closure declaring another number of parameters than its expected function type has, or none without a header where two or more are expected (naming the expected types, with help writing the header, `implicit-it`), an argument whose type is not assignable to its parameter (positional, named or trailing-lambda argument, struct constructor field, enum payload), a missing, duplicate or twice-assigned named argument, or a missing or duplicate struct field in a constructor call. Also indexing a `List` or a `String` with other than one index (`m[1, 2]`), and a call of a value whose type is neither a function type nor one with an `invoke` operator (`operator-conventions`). Also a function value with a receiver called without one (`f()` for `f: Scope.() -> Int`) where the innermost `this` does not have the receiver's type, saying how to pass one (`f(scope)` or `scope.f()`, `receiver-lambdas`); a closure's parameter count excludes its receiver. Also, for a vararg (`vararg`): a trailing lambda that would be one of its elements, a named argument between two of its elements, a named vararg argument that is not a spread, a spread mixed with elements or with another spread, and a spread for a parameter that is not a vararg (or for a callee without one). |
| `E4005` | `ReturnTypeMismatch` | A returned value (a `return` operand, an expression body, the final expression of a non-`Unit` block body, or a closure body) is incompatible with the declared or expected return type, including a value returned from a `Unit` function and a `return` outside a function. |
| `E4006` | `UnknownField` | A field does not exist on the struct, or member access on a non-struct or opaque type, including a member of a type parameter, which has none until traits exist. Also a method call `x.name()` with neither a field nor a visible extension function `name`, a `.` call of an extension on a nullable receiver (help suggests `?.`), an extension function read without a call (help suggests the call), a read `x.name` that finds no field, member property or extension property `name` (`core-library-in-prism`), and a call of an extension whose declared receiver the receiver does not match (`Box<Int>.inc` on a `Box<String>`; help names the declared receiver). A member or extension a library module declares on the receiver's type (a built-in type or a library type) gets help naming that module's import (`explicit-library`). |
| `E4007` | `VisibilityViolation` | A `package`-visible symbol is accessed from another package. Also a struct field not visible in the file (`private` outside its struct's file, `package` outside its package) that is read, written or borrowed (also through a bare name in an extension body, and in a path a closure captures), given by a construction of its struct, named by a named sub-pattern or a destructuring entry, or given by a positional struct pattern or by a positional sub-pattern before named ones (`field-visibility`). |
| `E4008` | `InvalidComposeContext` | A `compose fun` is called outside a composable function or closure, including in a parameter's default value, which is never a composable context, with a note saying default values are not composable (`compose-transform` D17). |
| `E4009` | `NonExhaustiveWhen` | A `when` in value position does not cover every value of its subject: some value matches no unguarded pattern. The message names one such value as a pattern (`Shape.Rect(_, _)`, `null`, `false`, `_` for an open type). |
| `E4010` | `DuplicateSymbol`, `UncallableExtension`, `InvalidTypeParameterName`, `BuiltinNameDeclared` | Two declarations in the same scope share a name, including a top-level declaration with the same name as an imported symbol. Also a top-level function, struct, enum or `val` named `Heap`, which would hide the built-in box constructor, or `List`, the built-in list type (`collections`), a duplicate type parameter of one declaration, or one named like a built-in type (`Int`, `Float`, `Double`, `Bool`, `Char`, `String`, `Unit`, `Nothing`, `Heap`, `List`), two extensions in one file with the same name on the same receiver type constructor (`fun Box<Int>.size()` and `fun <T> Box<T>.size()`) and the same context (both none, or the same type; extensions differing only by context coexist, and two top-level functions of one name are `E4010` whatever their contexts, `receiver-lambdas`), and an extension that could never be called: one named like a field of its receiver struct, named `clone` on a `Clone` type, or named like a member of its receiver type, an intrinsic extension a library module declares or an extension `/prism/core` declares on a built-in type, intrinsic or written in Prism (`toString` on `Int`, `Double`, `Bool` or `Char`, `length` on `String`, and `size`, `indices`, `isEmpty`, `add`, ... on `List`); the message names the declaring module (`standard-library`, `core-library-in-prism`). An extension property follows the same rules (`core-library-in-prism`): a property and an extension function of one name on one receiver type constructor in one file, a property named like a field of its receiver struct, and one named like a member are `E4010`. Also an operator function a built-in operator always serves, which could never be called (`operator-conventions`): an arithmetic, prefix or ordering function on `Int`, `Double`, `Char`, `Bool` or `String` for operand types the built-in operator accepts (`operator fun Int.plus(other: Int)`), and `get`, `set`, `iterator`, `hasNext`, `next` or `contains` on `List` or `Range`, or `get` or `set` on `String`, saying that the built-in operator always takes precedence; a shared and a `mut` `get` (or `next`) of one receiver are not duplicates. Also an extension named `drop`, in any file, on a struct or enum with a drop hook, which always takes precedence and is never called by name (`drop-and-clone-hooks`); a clone hook is not an extension named `clone` on a `Clone` type. A declaration named like an imported library name (`print`, `listOf`, `map`) shadows it, as for any import, and is not `E4010`; the extensions that the member module `/prism/core` declares on the built-in types are members in every workspace file, and other modules' intrinsic extensions (`Composition.recompose`) where their module is imported (`explicit-library`, `core-library-in-prism`); `Int.dp` and `Int.sp` of `/prism/compose/ui` are ordinary extension properties, which a file's own declaration shadows. A struct and a top-level `val` of the same file may share a name, the value being the struct's companion value; a `val` named like an imported struct is `E4010` (`ui-toolkit`). |
| `E4011` | `MissingReturnType` | A `public` or `package` function omits its return type. |
| `E4012` | `AmbiguousImport` | A name the file uses (as a value, callee or type) is exported by more than one of its imports, or an extension called on a receiver type is exported by more than one import. Importing both without using the name is accepted. |
| `E4013` | `CannotInferType` | A type cannot be inferred and must be written: a closure parameter with no expected function type, an unannotated private declaration whose inferred type depends on itself (such as a recursive function without a return type), a type argument of a generic call that neither the receiver, the expected type nor the arguments solve (`val o = none()`, `val o = Option.None`; help suggests writing the type arguments or annotating the expected type), or a generic function or variant constructor used as a value (`val k = keep`). Also an intrinsic of the bundled library named without a call (`val p = println` with `import /prism/core`), which has no code to name (`standard-library`). |
| `E4014` | `MemberOfUnimportedType` | A member of a struct or enum is used (a field read or written, its variants matched, the type constructed or a variant named) but the module defining the type is not a direct import; the message names the import to add. Receiving and passing along such a value is accepted. |
| `E4015` | `BreakOutsideLoop` | A `break` or `continue` has no enclosing loop in its function or closure body, including one inside a closure that sits in a loop. |
| `E4016` | `InvalidMarkerDeclaration` | A `: Copy` struct or enum has a field or variant payload that is not `Copy`, or a `: Clone` one has a member that is not `Clone`, where each type parameter occurring in a member type counts as satisfying the marker (`struct Box<T> : Copy { val v: T }` is accepted, `struct W<T> : Copy { val h: Heap<T> }` is not). | `E4017` | `CannotMoveOut` | A non-`Copy` value in a consuming position (an initializer, an assigned value, a by-value argument, a returned value) is taken from a field (also through a borrow, `Heap<T>` or a temporary), a safe navigation, an index or a top-level `val`, or out of a borrow or a box given where a value is expected (`take(u)` for `u: &User`, `take(h)` for `h: Heap<User>`, whose help suggests `h.unbox()`). Inside a closure, a variable the closure captures is borrowed and cannot move either (`run { take(s) }`). An element of a list in a consuming position (`val first = names[0]`) gets help suggesting `names[0].clone()` and `names.removeAt(0)` (`collections`). Also (`CannotTakeApart`, `MoveInGuard`): a pattern or destructuring declaration that moves a part takes apart a value that is not a whole owned local, parameter, consuming `this` or temporary (a field, a borrow's referent, a top-level `val`, a captured or default-borrowed binding, or a branch, block or `?:` result), or a guard moves a binding of its branch. Also (`TakeApartWithDropHook`, `drop-and-clone-hooks`) a pattern or destructuring declaration that moves a part out of a value whose struct or enum has a drop hook, at any depth, which would skip the hook, with help suggesting a borrow (`when (&s)`); binding `Copy` parts, wildcards and borrowing patterns stay accepted. |
| `E4018` | `NotCloneable` | `clone()` is called on a value whose type is not `Clone`: a struct or enum without `: Clone` or `: Copy` (or an instantiation whose marker parameters' arguments are not `Clone`), a function value, an unbounded type parameter (help suggests the bound `<T : Clone>`), a `List<T>` whose element type is not `Clone` (help names the element type) or an unknown type. |
| `E4019` | `NotAReference` | Prefix `*` writes through a value that is neither a reference nor a `Heap<T>` (`*x = 1` for `x: Int`); each `*` peels one reference or box layer. `*` is only allowed on the left of `=`; reads through references and boxes are implicit. |
| `E4020` | `WrongTypeArgumentCount` | A generic type, `Heap`, `List` or type parameter is written with the wrong number of type arguments (`val b: Box`, `Box<Int, Int>`, `Heap<A, B>`, `List<Int, Int>`, `T<Int>`), or a call gives the wrong number of explicit type arguments, or any to a callee that is not generic (`id<Int, Int>(1)`, `one<Int>()`). ## Design Rationale
- **One code per error kind, separate from message text.** Tooling and tests match on codes, so messages can improve without breaking them.
- **`E4011` instead of reusing `E4004`** (`resolve-nominal-type-annotations`): a missing return type is not a call error, and the type checker also runs without the ABI stage (unit tests, a future LSP), so it needs its own diagnostic rather than relying on `E3001`.
- **`E1007` retired, not reused** (`fix-cli-workspace-audit`): mutually recursive imports are valid because exported declarations carry explicit types, so Phase 1 can extract every file in a cycle without reading any body.
- **Site-specific mismatch codes** (`typechecker-soundness`): `E4002`, `E4004` and `E4005` all report a value whose type is not assignable, distinguished by where the expected type came from (an annotation or operand, a parameter, a return type), so tools can suggest the right fix.
- **`E4020` to `E4022`, one per fix** (`generics`): a wrong number of type arguments (fix the count), an unsatisfied bound (bound the caller's type parameter, or pass a `Copy` value) and a borrow in a type argument (take `&T` in the signature) each have their own fix, so one code for every generic error was rejected. Members of a type parameter, receivers that do not match a generic extension, duplicate type parameters, uninferable type arguments, conditional markers and passing a capturing closure to a generic parameter widen existing codes instead.
- **`E4012`, `E4013` and `E4014` are new kinds, not reuses** (`typechecker-soundness`): an ambiguous import is not an unresolved symbol (`E4001`), a type that cannot be inferred is not a mismatch, and a member of a type whose module is not imported is not an unknown field (`E4006`), so each needs its own code and its own help line.
- **`E4031` to `E4033`, one per fix** (`state-handles` D7; `E4033` retired by `owned-state`, whose state values borrow in every context): a write during composition is moved to a handler (`E4031`), a state created during composition is wrapped in `remember` (`E4032`), and a borrow of a state's value outside composition goes through `read`, `update` or `edit` (`E4033`). Kotlin reports none of them, because Jetpack's snapshots allow writes during composition and a lint reports unremembered state. Rejected: one code for all three, reusing `E4008`, and a warning for unremembered state.
- **`E5xxx` for the borrow checker** (`borrowck-moves`, user for the range). A flow-sensitive error is the borrow checker's and takes the next `E5xxx` code; later borrow-checker errors (conflicting borrows, escaping closures, dangling returned borrows) continue the range.
- **Borrow errors are structured and show related locations** (`borrowck-moves`). A borrow error has a primary label, related labels (where the value moved), notes and help lines, so a use after move can say where the value went, which a single span and help line cannot. The CLI renders each location with its own snippet and label, related ones in source order.
- **`E5003` to `E5007`, one per fix** (`borrowck-exclusivity`). A conflicting borrow or read (`E5003`: end the other borrow earlier), an assignment (`E5004`) or a move (`E5005`: clone first) of a borrowed value, a value that ends while borrowed (`E5006`: make it outlive the reference, or bind a temporary with `val`) and an escaping capturing closure (`E5007`: pass the value as a parameter). Rust's split of borrow-borrow (E0499, E0502) and use-borrow (E0503) conflicts was rejected, since their fix is the same; whether reads while mutably borrowed deserve their own code is open. `borrowck-elision` continues the range at `E5008`.
- **`E5008` and `E5009`, one per fix** (`borrowck-elision`). A returned borrow of memory the body owns (`E5008`, the name `docs/architecture.md` gave it: return the value instead) differs from one derived from an input the elision rule does not tie the result to (`E5009`, the "own code" of rule 2, also for function-typed parameters, a closure's captures and defaults' earlier arguments: return a borrow of a tied input or change the signature). The wording follows rustc's E0515 with Prism's "borrow". Rejected: one code for both; a code per `E5009` reason; rustc's "lifetime may not live long enough", which names lifetimes Prism has no syntax for.

Decisions from `generics` (planned autonomously on 2026-10-17, refined while implementing and reviewing the change, and logged in `docs/decisions-for-review.md`):

- **Three new codes, by fix.** `E4020` for the wrong number of type arguments (including none on a generic type in an annotation and any on a non-generic callee), `E4021` for an unsatisfied `Copy` or `Clone` bound, `E4022` for a borrow in a type argument; arity, bounds and borrows each have a different fix. The rest widens existing codes: `E2001` for the grammar, `E4006` for members of type parameters and mismatched receivers, `E4010` for type parameter names and one extension per receiver constructor, `E4013` for uninferable type arguments, `E4016` for conditional markers, `E4018` with a bound suggestion, and `E5007` for generic slots. Rejected: one code for every generic error.

Decisions from `codegen-core` (planned autonomously on 2026-10-17, refined while implementing and reviewing the change, and logged in `docs/decisions-for-review.md`):

- **`E6xxx` for code generation and the entry point, one code per fix** (D13 and D25): `E6001` (wait for the backend change its note names, or avoid the construct), `E6002` (add a `main`) and `E6003` (fix its signature). The entry point is checked at `prism run` rather than by the type checker, because `prism check` checks libraries, which have no `main`. Runtime errors are not diagnostics and carry no code.

Decisions from `string-templates` (planned autonomously on 2026-10-17, refined while implementing and reviewing the change on 2026-10-18, and logged in `docs/decisions-for-review.md`):

- **`E4026` for every part without a text form** (D8 of `string-templates`): nullable, `Unit`, function, type parameter, and structs or enums without a usable `toString()` share one code, since the rule is one ("a part needs a text form"), and the message and help name the reason and the fix. Rejected: reusing `E4004` (a part is not a call argument) or `E4006` (the user never wrote `toString`), and one code per reason.

Decisions from `monomorphization` (planned autonomously on 2026-10-17, implemented on 2026-10-18, and logged in `docs/decisions-for-review.md`):

- **`E4027` for polymorphic recursion and non-regular generic types, `E6004` across files** (D8, D9 and D15): one code for a growing instantiation cycle of a file, whether through calls of generic functions or through the fields of generic types, since the fix is the same; the same mistake spread over an import cycle is found only when the program is compiled, a different stage, so it takes the next code of that stage. Calls of generic functions left `E6001`, since instances run.
- **Function values and closures left `E6001`** (`closures` D13): closures, function values and the aggregates holding them run, so what `E6001` still names is values of unknown type and conversions the backend does not lower, of which the type system produces none; composable functions and closures left it too (`compose-transform` D17).

Decisions from `escaping-closures` (planned autonomously, revised for compile speed, and logged in `docs/decisions-for-review.md`):

- **`E4028` for captures a closure cannot take by value, one code for both kinds** (D5): a `var` and a non-`Copy` value its builder does not own are both fixed by making a `val` the closure can take, so they share a code, which the type checker reports because it decides captures (D2). `E5007` keeps values that may hold a borrow, fixed by not capturing one.
- **`E5007` narrows to escaping values that may hold a borrow** (D6): a capturing closure that escapes owns its captures instead of being rejected, so only a closure owning a reference, a borrowing closure or an unmarked function-typed parameter is rejected at an escape, now including `escaping` parameters.

Decisions from `explicit-library` (planned and implemented on 2026-10-20, and logged in `docs/decisions-for-review.md`):

- **Import help, not new codes** (D8, D15). A missing library import is an unresolved name (`E4001`) or member (`E4006`) like any other, so it keeps those codes and gains a help line naming the import, filled by the driver from a library index built only on that error path. A library type named in an annotation without its import is `E4001` under a new kind, `UnresolvedTypeName`, because it was accepted as an opaque type before; the kind will also serve when every unknown type name is rejected. Rejected: a dedicated "missing library import" code, which would make the code depend on whether the library happens to declare the name.
