# Tasks

Fixtures go under `crates/prism-cli/tests/fixtures/<spec>/`, one case per scenario, or per form of a scenario with several (`<scenario-slug>--<form>`), as the header of `fixture_tests.rs` describes. Programs are executable cases (`// run: <status>` with `stdout.snap` and `stderr.snap`); from task 6.2 on, every executable case runs with `--check-allocations`. Scenarios about `prism dump-clif`, about whether a program allocates, and about leaks or invalid frees that no Prism program can cause are Rust tests (runtime, codegen or CLI tests), not fixtures. Read every blessed snapshot against its scenario's THEN before committing it. `codegen-aggregates` must be archived before this change starts, since its layouts, calling convention and support check are what tasks 4 and 5 extend.

## 1. Runtime: the allocator and allocation checking (D8, D13, D14, D17)

- [x] 1.1 Add `crates/prism-runtime/src/allocation.rs` with `pub extern "C" fn prism_rt_allocate(size: usize, alignment: usize) -> *mut u8` and `prism_rt_free(pointer: *mut u8, size: usize, alignment: usize)` over `std::alloc::{alloc, dealloc}`, an `AtomicBool` checking flag, and, when it is set, a map from address to `(size, alignment)` in the runtime state, with totals for `pub fn allocation_statistics() -> AllocationStatistics` (allocations made, live allocations, live bytes). A size that does not fit a `Layout` or a null result calls a new `panic::panic_without_location(PanicKind::OutOfMemory, "")`, which flushes and writes `panic: out of memory` alone; a free the map does not match flushes, writes `allocation check: freed memory that is not allocated` and exits with the new `ALLOCATION_CHECK_EXIT_STATUS` (102). Add both functions to `RUNTIME_FUNCTIONS` and `allocation.rs` to the sources the table test reads. Verify with runtime unit tests: an allocation and its free leave no live allocation; a free with another size, of an unknown address or twice is reported (test the matching through a function returning the verdict, since reporting exits); `PanicKind::OutOfMemory` has the message `out of memory`; and an oversized request is classified as out of memory.
- [x] 1.2 Make `start` take the checking option (`start(arguments, check_allocations)`), resetting the map and totals, and add `pub extern "C" fn prism_rt_register_top_level_value(storage: *mut u8, drop: extern "C" fn(*mut u8))`, recorded in registration order. Make `finish` flush, then in check mode run the registered drops in reverse order and, when live allocations remain, write `allocation check: allocations still live at exit: <n> (<b> bytes)` and return 102 instead of 0. Verify with runtime unit tests for "A leak is reported" (an allocation never freed, through a report function that `finish` uses), for a registered value whose drop frees the only allocation leaving nothing to report, and that without the option nothing is tracked.

## 2. Runtime: strings (D2, D3, D4, D7, D17)

- [x] 2.1 Add `crates/prism-runtime/src/string.rs` with `#[repr(C)] pub struct PrismString { pointer, byte_length, character_count, capacity }` (D2's invariants in its documentation, a static empty text for empty results) and the `extern "C"` functions of D7: `prism_rt_string_concatenate`, `prism_rt_string_equals`, `prism_rt_string_character` (ASCII fast path when the counts are equal, otherwise a scan; out of range raises the new `PanicKind::StringIndexOutOfRange` with the detail `<i> out of range for length <n>` at the given location), `prism_rt_string_clone` (a copy for capacity 0, an exactly sized new buffer otherwise), `prism_rt_string_drop` and `prism_rt_print_string`; every buffer is allocated with `prism_rt_allocate`. Verify with runtime unit tests that each gives exactly what the corresponding `prism_rt_print_*` writes (`-42`, `0.30000000000000004`, `1.0E7`, `4.9E-324`, `true`, `é`) and that `Bool` text allocates nothing.
