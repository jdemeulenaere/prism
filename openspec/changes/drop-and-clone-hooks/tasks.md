- [x] 2.3 Type checker (`crates/prism-typechecker/src/checker/operators.rs`): the hook rules in `check_operator_declaration`: same file as a struct or enum (not intrinsic, not built in), no visibility modifier, receiver mode (`mut` for `drop`, shared for `clone`), no parameter, result `Unit` or `T`, type parameters exactly the type's in order (unbounded for `drop`; marker parameters may be bounded by `Clone` for `clone`), no `compose`, context or defaults; `drop` on a `: Copy` type; a `: Clone` type with a drop hook and no clone hook (help suggesting `operator fun T.clone(): T`); `clone` on a type without `: Clone` (help suggesting the marker) or with `: Copy`. - [x] 2.4 Resolution: a drop hook is a member `drop` of its type for method calls; a call resolving to it, through `&`, `&mut`, `Heap<T>` and `?.`, is the new `TypeError::DropHookCalled` (`E4036`, `error.rs`, rendered in `crates/prism-cli/src/diagnostics.rs` with the help of D3); an extension named `drop` on a type with a drop hook is `E4010` (the member-shadowing check of `register_extension_decl`).
