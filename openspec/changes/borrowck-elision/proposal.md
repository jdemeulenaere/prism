# Proposal: borrowck-elision

## Why

Since `borrowck-exclusivity`, a call's result keeps the borrows of the arguments it is passed, but nothing checks that the callee only returns what its callers assume: `fun f(): &Int { val n = 1; return &n }`, `val R: &Int = &1`, a closure returning a borrow of its own local, a method returning a borrow of a parameter other than its receiver, `fun call(h: () -> &Int): &Int = h()` and `fun m(a: String, b: &String = a)` all pass `prism check` and hand out dangling or unprotected borrows. A by-value `Int` parameter stored through a `&mut &Int` parameter (`*slot = &v`) is accepted too, and lending a `(&mut T)?` where a `(&mut T)?` is expected crashes MIR lowering. This change, step 9 and the last step of "the road to the borrow checker" in `ROADMAP.md`, adds the callee's half of the four lifetime elision rules of `docs/architecture.md` §3, so that caller and callee agree on every returned borrow from the signature alone, and settles the follow-ups `ROADMAP.md` assigns to it.

## What Changes

- **The four elision rules, from the signature alone.** A function's input borrows are its parameters whose type contains a reference outside a function type and the receiver of a non-`consuming` method. Rule 1 (one input borrow) and rule 3 (several) tie a returned borrow to every input borrow, rule 2 (a method with a borrowed receiver) to the receiver only, rule 4 (none) to nothing. One function computes the tied inputs from parameter types and whether the callee has a receiver, and both the caller (what a call's result keeps borrowed) and the callee (what its body may return) use it, so they agree by construction, also across files through the imported ABI.
- **Rule 2 at call sites.** A call of a method with a borrowed receiver keeps only the receiver borrowed: `val c = t.captain(&s); s = "y"; greet(c)` is now accepted. The receiver operand is known from the callee's declaration path, which already names the receiver type, so MIR needs no new field.
- **The callee's check** (`references`). At each write of the return place, the borrow checker rejects a borrow of a local, a temporary or a by-value parameter as `E5008` `DanglingBorrowReturn` (rule 4's case and every rule's), and a borrow derived from a parameter the result is not tied to as `E5009` `UntiedBorrowReturn`: another parameter of a method (rule 2), a function-typed parameter's result when its type has no input borrow, a closure's capture when its type has one, or, in a default value, a by-value or `&mut` earlier parameter. Borrows of top-level `val`s hold nothing and are valid everywhere, including from functions with no input borrows; a top-level `val` cannot hold a borrow of its own temporary.
- **Function types elide by the same rules.** A call of a function value whose type has input borrows keeps those arguments borrowed, and one whose type has none keeps the function value's own borrows; so a closure whose type has input borrows may return borrows derived from its reference parameters, one whose type has none borrows of what it captures, and neither borrows of its own locals. So `fun apply(g: (&Int) -> &Int, v: &Int): &Int = g(v)` is accepted (orchestrator decision) and `fun call(h: () -> &Int): &Int = h()` is not. An extension cannot be a function value, so rule 2 never applies to one.
- **Default values.** A default may return borrows of its slot (a borrowed temporary), of top-level values, and of what an earlier shared reference parameter or a `fun` receiver refers to, and nothing else; a caller keeps exactly those borrowed, and no longer the generator's own borrow of each argument's temporary, so `val h = u.hi()` for `fun User.hi(n: &String = name): &String` no longer reports a dropped temporary. A `mut fun` default borrowing `this` (`mut fun User.rename(n: &String = name)`) is rejected at its declaration (`E5009`) instead of at every call with a misleading `E5005`. **BREAKING** for defaults that borrow a by-value or `&mut` earlier parameter.
- **Borrows stored through inputs.** A body may store a borrow of its inputs through a `&mut R` parameter or into a captured variable, which callers already assume. By-value parameters now end when the body returns, so storing a borrow of one there (`*slot = &v` for `v: Int`, a closure writing `r = &x` for its parameter `x`) is `E5006`, labelled at the parameter; an `E5006` whose later use is the caller's labels the parameter through which the caller sees it, not the signature.
- **`(&mut T)?` arguments are reborrowed** (orchestrator decision). Lending a `(&mut T)?` place where a `(&mut T)?` is expected reads its tag and passes `null` or a wrapped mutable reborrow of the payload's referent, as lending it as a `(&T)?` does, so the binding stays usable; it no longer crashes MIR lowering.
- Not in scope: lifetime annotations (the zero-cost memory-safety invariant has none); counting function-typed parameters as input borrows; escaping, move-capturing closures and the escape relaxations left to `closures`; lifetime extension through assignments.

## Capabilities

### New Capabilities
None. The `references` spec's purpose already reserves "what a function may return a borrow of" for this change.

### Modified Capabilities
- `references`: adds "The Elision Rules Tie a Returned Borrow to Inputs", "Returned Borrows Derive Only From Tied Inputs", "Function Types Elide by the Same Rules", "Default Values Borrow Only Through Shared References", "Borrows Stored Through Inputs Outlive the Call" and "Returned Borrow Diagnostics Name the Source"; modifies "Passing a Mutable Borrow Reborrows It" (`(&mut T)?` too), "Calls Returning References Keep Their Inputs Borrowed" (rule 2 at call sites, exact default results) and "Lifetime and Escape Diagnostics Show Where the Value Ends" (parameter labels).
- `mir`: modifies "Optional Mutable Borrows Are Reborrowed" (a `(&mut T)?` lent as a `(&mut T)?`) and "Calls Name Their Callee" (an extension call's first operand is its receiver).

## Impact

- `crates/prism-borrowck`: new modules `elision.rs` (the tied inputs of a signature) and `returns.rs` (the callee's check, `E5008` and `E5009`); `borrows.rs` gives every argument whose type carries loans its own input; `loan_flow.rs`'s `call_items` uses `elision.rs`; `conflicts.rs` ends by-value parameters at each return and labels parameters; `error.rs` gains two kinds; `lib.rs` runs the new check.
- `crates/prism-mir`: `Callee::has_receiver` and `BodyOwner::has_receiver`; `build/place.rs` and `build/comparison.rs` lower a `(&mut T)?` place lent as a value as an optional mutable reborrow.
- `crates/prism-cli`: fixtures under `tests/fixtures/references/` (including cross-file ones), `mir/` and `diagnostics/`; rendering tests; the `ownership` fixture form that borrowed a by-value earlier parameter in a default is rewritten.
- `openspec/specs/diagnostics/spec.md`: catalog rows `E5008` and `E5009`; `E5003` and `E5006` rows updated.
- `docs/architecture.md` §3: on archive, "The Four Lifetime Elision Rules" and the note on the ABI move into the specs, which completes the memory model's borrow-checker requirements. `ROADMAP.md`: step 9, the Phase 2 borrow-checker item and the follow-ups assigned to this change are ticked.
