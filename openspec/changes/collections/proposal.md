# Proposal: collections

## Why

Prism has no collection type. A program cannot hold a variable number of values, so a todo list, the children of a UI node, a parsed argument list or a stack cannot be written, and `for` iterates only `Range`. Milestone 2 needs one: the todo app keeps a `List<Todo>` in state, and `docs/architecture.md` §5 already plans `for (todo in todos.value)` in a composable. This change is item 24 of "Then: the road to Milestone 2" in `ROADMAP.md`, and the deferred item "Iterating anything other than `Range` in `for` loops". It adds a growable, single-owner `List<T>`, decides how its elements are read, written and borrowed under the borrow checker, and how `for` iterates it before traits exist. It also decides whether `List<T>` is a compiler built-in now or waits for the bundled library that `standard-library` plans (D1).

## What Changes

- **One built-in type, `List<T>`** (D1, D2, D3). A growable list of elements of a borrow-free type `T`, owned by one value like a `String`: three words (a buffer pointer, a size and a capacity), never `Copy`, `Clone` exactly when `T` is, invariant in `T`, and an indirection, so `struct Node { val children: List<Node> }` is finitely sized. `List` is a built-in type name like `Heap` (a declaration named `List` is `E4010`), recorded in the ABI. There is no `MutableList`: a list is mutable through a mutable place (a `var`, a `var` field, a `&mut`), as every other value is.
- **Construction with `listOf`** (D4). `listOf(1, 2, 3)`, `listOf<String>()` and `val xs: List<Int?> = listOf()` build a list holding exactly its arguments, typed as a generic function of that many parameters of type `T` (joins, the expected type and explicit type arguments work as for any generic call; an empty `listOf()` with no expected type is `E4013`). `listOf` is a built-in function that a declaration of that name shadows, as `print` is.
- **Built-in members** (D5, D6). `size` and `indices` (read without parentheses, like `length`), `isEmpty()`, `isNotEmpty()`, `contains(element)`, `indexOf(element)`, and the mutating `add(element)`, `insert(index, element)`, `removeAt(index)`, `removeLast()`, `reverse()` and `clear()`, plus the built-in `clone()`. They are typed as generic extension signatures with receiver modes (`mut fun` for the mutating ones), so receivers are borrowed, a mutating call needs a mutable place (`E4003` for a `val` list), and arguments are checked like any extension's. They take precedence over extensions, and an extension of the same name on `List` is `E4010`.
- **Elements are places** (D7). `xs[i]` names element `i` of the list, read through any `&`, `&mut` and `Heap` layers. A `Copy` element is copied out, a non-`Copy` one cannot be moved out (`E4017`, help suggesting `.clone()` or `removeAt`), `&xs[i]` and `&mut xs[i]` borrow it in place, `xs[i] = v` drops the old element and moves `v` in, `xs[i] += 1`, `xs[i].name = "x"` and `xs[i].add(1)` work, and argument and receiver positions borrow it where it lives. Writing needs a mutable place (`E4003`).
- **Bounds checks** (D8). Every element access, `insert`, `removeAt` and `removeLast` checks its index after its operands are evaluated; a bad index ends the program with the runtime error "list index out of range" (status 101), located at the access, and `removeLast()` of an empty list with "list is empty".
- **`for (x in list)`** (D9, D10). `for` iterates a `List<T>` as well as a `Range`. The list is borrowed for the whole loop (a temporary list lives until the loop ends) and `x` is a `&T` to each element in order, or a `&mut T` when the iterable is `&mut xs`. Since operators, output and value positions read through references, `for (n in numbers) total += n` reads as in Kotlin. Iterating anything else is still `E4002`. There is no user-visible iteration protocol yet: `Range` and `List` are the two built-in iterables, which the MIR lowers through one shared iteration shape.
- **Borrowing follows from existing rules** (D11). An element borrow borrows the list, so holding `&xs[0]` across `xs.add(4)`, or calling `xs.add` inside `for (x in xs)`, is the existing `E5003`. Two element places of one list always overlap. Storing a function value in a list is storing it in a generic slot.
- **Equality** (D12). `==` on lists, `contains` and `indexOf` compare elements with `==`, allowed exactly where `==` on the element type is: comparing lists whose element type mentions a type parameter is `E4002`, as comparing two `T`s is.
- **Backend and runtime** (D13 to D16). A list is `{ pointer, size, capacity }`, 24 bytes; an empty list and a list of zero-sized elements allocate nothing. `add` writes in place and calls the runtime only to grow, doubling the capacity from 4. A new `crates/prism-runtime/src/list.rs` grows, opens and closes gaps, reverses and frees buffers through the existing allocator. Per-type glue drops every element in order and frees the buffer, clones into an exactly sized buffer, and compares and searches lists through the equality glue of `heap-boxes`. `prism dump-layout` shows lists.
- **Fixtures and a benchmark.** Every runtime scenario is an executable fixture under `--check-allocations`, including nested lists, lists in structs, lists of strings and closures, generic code over lists, top-level lists, and a million `add`s. An ignored release benchmark reports the time of a million `add`s against a 20 ms target.
- **Not in scope** (D17). `forEach`, `map`, `filter` and the other higher-order helpers: they are ordinary Prism code over this change's members, so they belong in the bundled library of `standard-library`, whose `ROADMAP.md` item gains them. Also deferred: a user-visible iteration protocol, consuming iteration, iterating a `String`, `List(size) { init }`, `vararg`, `remove(element)`, `first()`/`last()`/`getOrNull`, sorting, `subList`, slices, capacity control (`ensureCapacity`, `trimToSize`), a null niche for `List<T>?`, printing a list, maps and sets, and eliding bounds checks the loop proves.

## Capabilities

### New Capabilities
- `collections`: the `List<T>` type and its markers, `listOf`, the built-in members and their precedence over extensions, element places, iteration with `for`, element equality, and how the borrow rules apply to elements and loops.

### Modified Capabilities
- `loops`: "For Loops Over Ranges" also accepts a `List`, whose iteration `collections` specifies.
- `typed-tree`: a `for` loop records how it iterates; assignments may target elements; list operations are built-in calls and elements are index places.
- `mir`: index projections become valid on lists; a `for` loop over a list borrows it once and walks it by index.
- `code-generation`: the representation of a list, its growth, its glue, bounds checks and the layout dump.
- `execution`: the runtime meaning of building, reading, writing, growing, shrinking, iterating, comparing, cloning and dropping lists, and the two new runtime errors.

## Impact

- `crates/prism-typed-tree`: `Type::List`, its rendering and substitution; `BuiltinFunction` variants for `listOf` and each member; a `ForIteration` on `StatementKind::For`; `ExpressionKind::Index` produced for lists; `BorrowOrigin::Iteration`; validation.
- `crates/prism-abi`: `AbiType::List`, hashed and rendered.
- `crates/prism-typechecker`: `List<T>` in `lower_type` and `bind_type_name` with the reserved name; the built-in member table as `Extension` records with a built-in callee, consulted in `infer_method_call` and `build_member_access`; `listOf` in `infer_call_expr`; indexing in `infer_expr` (`ExprKind::Index`) and `infer_place`, assignment targets and E4017 sources; `for` in `check_statement`; markers, borrow-free checks, `E4023`, patterns and exhaustiveness treating `List<T>` like `String`.
- `crates/prism-mir`: `Projection::Index` typed and validated for lists (`types.rs`, `validate.rs`), element places in `build/place.rs`, the list iteration in `build/control_flow.rs`, built-in calls in `build/call.rs`.
- `crates/prism-borrowck`: element places owned by their list in `places.rs`, index locals read at each access (`uses.rs`), assignments to elements in drop elaboration, the loop borrow labelled in diagnostics.
- `crates/prism-codegen`: the list layout (`layout.rs`, `representation.rs`), element addresses with bounds checks and the members (`lower.rs`), list drop, clone, equality and index-of glue (`glue.rs`), `supported.rs`, the layout dump.
- `crates/prism-runtime`: `list.rs`, a reallocation in `allocation.rs`, and the two runtime errors in `panic.rs`.
- `crates/prism-cli`: fixtures under `collections/`, `loops/`, `typed-tree/`, `mir/`, `code-generation/` and `execution/`; a list benchmark beside `run_timing.rs`; `examples/run/` uses a list.
- `ROADMAP.md`: item 24 records the shape this proposal chose, and item 26 (`standard-library`) gains the higher-order helpers (D17).
- Specs: the deltas above. The diagnostics catalog rows `E4002`, `E4003`, `E4010`, `E4017` and `E4023` are widened, edited directly. `docs/architecture.md` is unchanged: it plans no list design, and §5's `List<Todo>` state now has a type.
- **Prerequisites:** `payload-patterns`, `heap-boxes` (equality glue, `Heap` read-through rules that indexing follows), `monomorphization` (lists in generic code), `closures` and `escaping-closures` (function values held in lists) must be archived first; `instance-cache` and `string-templates` are not needed. See `design.md`, "Baseline".
