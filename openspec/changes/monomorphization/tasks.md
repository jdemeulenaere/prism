## 1. The instantiation graph and polymorphic recursion (D8, D9, D15)

- [x] 1.1 Create `crates/prism-typed-tree/src/instantiation.rs` with `InstantiationNode { generic: String, parameter: u32 }`, `InstantiationEdge { from, to, grows: bool, span: Span }`, `pub fn grows(argument: &Type, parameter: u32) -> bool` (false exactly for `Parameter(parameter)` and `Parameter(parameter)?`), `pub fn edges_of(generic, parameters, callee, arguments, span) -> Vec<InstantiationEdge>`, and `pub fn growing_cycle(edges: &[InstantiationEdge]) -> Option<Vec<InstantiationEdge>>` (Tarjan's components, then a path from a growing edge's target back to its source within its component). Export it from `lib.rs`. Verify with unit tests: a self edge that grows, a two-node cycle with one growing edge, a cycle without growth, a `T?` argument, and a growing edge outside any cycle.
- [x] 1.2 Create `crates/prism-typechecker/src/recursion.rs` with `check_polymorphic_recursion`, run after a file's bodies are checked. It builds edges from every typed-tree `Call` with `Callee::Function` naming a generic of the file's own module (in function bodies, default value bodies and closures, attributed to their owner function), and from every application of a generic struct or enum in the field and payload types of the file's own generic types, through `Heap`, nullables and type arguments but not function types (D9). For each growing cycle, report `TypeError::PolymorphicRecursion { cycle, argument, span }` (`E4027`) at its growing edge, once per cycle. Skip types that `check_finite_sizes` reported. Render it in `crates/prism-cli/src/diagnostics.rs` with the cycle's generics and the growing argument. Verify with fixtures under `generics/` for every scenario of "Polymorphic Recursion Is Rejected" and "Non-Regular Generic Types Are Rejected", and that `cargo test -p prism-typechecker` passes.
