# Proposal: standard-library

## Why

Everything a Prism program can call without declaring it is hard-coded in the type checker: `print` and `println` are a special case in `infer_call_expr`, `toString()` and `length` are special cases in `infer_method_call` and `build_member_access`, and `collections` adds a table of `List` members and a variadic `listOf`. Each new built-in costs a typing special case, a lowering special case and a hand-written precedence rule, and none can be formatted, documented, imported or shadowed like code. The compose engine needs dozens more (`remember`, `mutableStateOf`, `State<T>.value`, `Column`, `Button`, `Text` with named parameters and defaults), and the higher-order list helpers (`forEach`, `map`, `filter`) are ordinary Prism code that has nowhere to live. This is item 26 of "Then: the road to Milestone 2" in `ROADMAP.md` (`docs/architecture.md` §5, "Bundled Standard Library and Compose Prelude", decision D2 of `compose-architecture`), extended by `collections` (D1, D17) with the list helpers and members. It makes the compiler ship Prism source under the reserved root package `prism`, gives that source two declaration forms the workspace may not use, `external fun` and `intrinsic`, and puts a prelude in scope in every file, so that `compose-transform`, `state-handles` and `ui-toolkit` add library modules rather than type-checker tables.

## What Changes

- **A bundled library** (D1, D3). A new crate, `crates/prism-library`, holds the library's `.prism` files and embeds them in the `prism` executable with `include_str!`. Library files are ordinary compilation units: Phase 1 extracts their ABI, Phase 2 checks them, `monomorphization` instantiates their generics and the backend compiles them, each into its own unit. They are cached like workspace files. Their source text is in their keys and the compiler identity covers the executable that embeds them. Only the modules a program reaches are parsed.
- **The reserved root package `prism`** (D2). A root-anchored import whose first segment is `prism` and which has a second segment (`import /prism/system`) resolves to the bundled module, whatever the workspace root holds. A workspace file declaring `package prism` or `package prism.<anything>` is rejected with the new `E1008` (`ReservedPackage`). Library files import only library modules. Diagnostics and runtime errors show a library file by its module path (`prism/collections.prism`), which no workspace file can have.
- **A prelude** (D4). The public declarations of the prelude modules, `/prism/core` and `/prism/collections`, are in scope in every workspace file without an import. They are found after the file's own declarations and its explicit imports, so a declaration or import of the same name shadows a prelude name without `E4010` or `E4012`, as `print` and `listOf` are shadowed today. The prelude is built into one shared scope once per process, so a file pays a lookup on a miss rather than an ingestion of the library's ABI. Prelude modules count as direct imports for check keys and instance planning. Library files get no implicit prelude.
- **`external fun`** (D5). A body-less declaration of a runtime entry point, named by its C symbol (`private external fun prism_rt_exit(status: Int): Nothing`), called directly by symbol with the platform's C calling convention and no function-table slot, and never reloaded. Its machine signature is the one a Prism function of that signature has: scalars by value, every value held in memory (strings, structs, enums, nullables, lists, boxes, function values) and every reference by address, and a result held in memory written through an address passed first. An external is not `public`, not generic, not an extension, not `compose`, has no defaults and returns no reference. The backend checks each external against the runtime's function table and reports a missing symbol or a different machine signature as the new `E6005` (`ExternalMismatch`).
- **`intrinsic` declarations** (D6, D7). `intrinsic fun` and the new `intrinsic val` extension property (`public intrinsic val String.length: Int`) declare a signature whose calls the compiler lowers itself, as `Callee::Builtin` calls in the typed tree. Most intrinsics are typed exactly by their declared signature. Three are typed by a rule that their signature cannot express until overloading, `vararg` or traits exist: `print` and `println` (an optional argument with a text form) and `listOf` (any number of elements). `contains` and `indexOf` also need `==` on the element type at each call. The compiler holds a catalog of its intrinsics, and a library declaration that names an unknown intrinsic or gives another signature is the new `E4029` (`InvalidLibraryDeclaration`), as are the external rules above. **Intrinsic extensions are members** of their receiver type: they take precedence over every extension, and a workspace extension of the same name on that type is `E4010`, which is today's rule for `length`, `toString` and the list members, now read from declarations.
- **Library-only forms** (D12). `external` and `intrinsic` are contextual modifiers, after the visibility and before `compose`. A workspace file using either is rejected in Phase 1 with the new `E3002` (`LibraryOnlyDeclaration`). A `fun` without a body is now a syntax error (`E2001`) unless it is `external` or `intrinsic`, where the parser accepted it silently before. **BREAKING** only for that silent case.
- **What moves into the library now** (D8, D9). `/prism/core` declares `print`, `println`, `toString()` of `Int`, `Double`, `Bool` and `Char`, and `String.length`. `/prism/collections` declares `listOf`, the list members of `collections` (`size`, `indices`, `isEmpty`, ..., `clear`) and new helpers written in Prism: `forEach`, `forEachIndexed`, `map`, a consuming `filter`, `any`, `all`, `none`, `count`, `indexOfFirst`, `fold`, `sumOf` and `joinToString`. `/prism/system` (imported, not in the prelude) declares `exitProcess`, the first external. The type checker's hand-written tables of these built-ins are removed. `clone()`, `Heap(...)`, `unbox()`, indexing, operators, `Range` and the built-in types stay in the compiler.
- **`print` of any type with a text form** (D9). `print(x)` and `println(x)` accept any argument a string template part accepts, through the same rule: a `String` borrowed, a scalar by value, any other type through the `toString()` that `x.toString()` resolves, called on a shared borrow and dropped after printing. A nullable, `Unit`, function or type-parameter argument is `E4026`, as in templates, instead of `E4004`.
- **`exitProcess(status)`** (D10). It flushes the output and ends the process with the low 8 bits of `status`, running no drop and no allocation check, as a runtime error does. Under `prism run --watch`, it ends the program's run as `main` returning does.
- **Checking the library** (D13). A test checks every bundled module with `prism check`'s pipeline, checks that `prism fmt --check` accepts it, checks that the prelude modules export disjoint names, checks that the embedded module list matches the library directory, and checks every external against the runtime table. Fixtures can add test modules to the library with a `// library:` header, so that the library-only diagnostics have real-source cases.
- **Not in scope** (D14 and follow-ups). `/prism/compose` and `/prism/ui` are created by `compose-transform`, `state-handles` and `ui-toolkit`. Each adds its module and, for `/prism/compose`, its prelude entry. Also deferred: intrinsic types (`State<T>`, which `state-handles` adds on this design), extension properties outside the library, `Range` and `Heap` as library declarations, `abs`/`min`/`max` and other math (no overloading yet), `error`/`require`/`check` (they need the caller's location), reading program arguments and standard input, a default `joinToString` transform, printing nullables, precompiled or cached library ABIs, skipping the code of library units a program never calls, an override directory for library development, and materializing the library sources for editors.

## Capabilities

### New Capabilities
- `standard-library`: the bundled library and its modules, the prelude and how its names are found, the `external` and `intrinsic` forms and their rules, intrinsic members, the library-only diagnostics, `exitProcess`, and how the library itself is checked.

### Modified Capabilities
- `package-resolution`: root-anchored imports of `/prism/...` resolve to the library, and the reserved package `prism` (`E1008`).
- `syntax`: the `external` and `intrinsic` modifiers, body-less declarations only for them, and `intrinsic val` extension properties. The span scenario of "Lexical Tokenization and Escape Sequences" now uses `intrinsic fun`.
- `type-system`: "Output Built-In Arguments" accepts any type with a text form, and "Output Built-Ins Are Found Last" is replaced by the prelude rule of `standard-library`.
- `extension-functions`: members include the library's intrinsic extensions, and extension lookup ends with the prelude.
- `collections`: the list members are intrinsic declarations of `/prism/collections`, `listOf` is a prelude name, and the higher-order helpers are added.
- `compilation-and-abi`: the ABI records intrinsic and external declarations and intrinsic extension properties, and library files are ordinary units.
- `build-cache`: prelude modules count as direct imports in check keys, and `--explain-cache` lists library files.
- `code-generation`: externals are called directly by symbol and checked against the runtime (`E6005`).
- `execution`: printing a value through its `toString()`, `exitProcess`, and runtime errors located in library files.
- `formatting`: library declarations are printed in canonical modifier order.

## Impact

- New `crates/prism-library`: the library's `.prism` files under `prism/`, the module list, the prelude list and the `Library` type.
- `crates/prism-resolver`: library nodes (`SourceOrigin::Library`, virtual paths), `/prism/...` import resolution, implicit prelude edges, `E1008`.
- `crates/prism-parser`, `crates/prism-ast`: `external`/`intrinsic` modifiers, `DeclarationBody` kinds, `ExtensionPropertyDecl`, the body-less rule.
- `crates/prism-abi`: `E3002`, intrinsic and external kinds and extension properties in `ExportedSymbol`, hashed and rendered.
- `crates/prism-typechecker`: `PreludeScope`, the intrinsic catalog and `E4029`, members from intrinsic declarations (replacing the `print`, `toString`, `length` and list-member special cases), the text-form rule for `print`, `Callee::External`.
- `crates/prism-typed-tree`, `crates/prism-mir`, `crates/prism-borrowck`: `Callee::External`.
- `crates/prism-codegen`: direct external calls, the runtime-table check and `E6005`.
- `crates/prism-runtime`: `prism_rt_exit` and its watch-mode hook.
- `crates/prism-formatter`: the new modifiers and body-less declarations.
- `crates/prism-cli`: the library in the graph and the checker, library lines in `--explain-cache`, the fixture runner's `// library:` header, library tests, fixtures under `standard-library/` and elsewhere, compile-timing and startup measurements.
- Specs: the deltas above, plus the diagnostics catalog (`E1008`, `E3002`, `E4029`, `E6005`, `E4026` and `E4010` widened), edited directly. `docs/architecture.md` §5: the library requirement is implemented except its compose prelude scenario, which moves to `compose-transform`'s text.
- **Prerequisites:** `monomorphization`, `instance-cache`, `closures`, `escaping-closures`, `collections` and `hot-reload` are archived first. See `design.md`, "Baseline".
